# 01_封面

各位老师好，我是张艺鹏，今天向各位汇报我的学位论文选题报告，题目是《融合推荐机制校准的社交仿真平台设计与实现》。我的责任导师是黄浩程老师，研究方向为数据智能技术与应用，培养单位是媒体融合与传播国家重点实验室。这项工作的核心，是从真实传播数据出发校准推荐机制参数，再注入一个大小模型协同运行的在线社交仿真平台。下面我从六个方面展开。

# 02_目录

整个汇报围绕一个核心问题：如何从真实传播数据校准推荐机制参数，并注入由 LLM Agent 与规则 Agent 协同运行的社交仿真平台。我将分六章逐层展开——选题背景与研究意义、国内外研究现状、研究目标与创新点、技术路线与方案、可行性分析，最后是进度安排。

# 03_章节页研究动因

首先是选题背景。为什么要做一个可校准的社交仿真？有三点动因。第一，社交媒体已经成为公共议题扩散、舆论形成与平台治理的重要空间。第二，真实平台存在算法黑箱，曝光日志难以获取，对照实验又受到伦理与监管的限制。第三，也是最关键的——仿真的真正价值不只是复现宏观现象，而是要解释用户行为、网络结构与平台机制如何共同生成传播结果。这意味着研究要从「结果描述」走向「机制解释」，而推荐曝光正是串联信息接触、互动行为与立场变化的关键环节。

# 04_研究意义

由此引出本课题的研究意义，可以从三个层面看。理论上，我们把推荐曝光从平台背景提升为传播过程中的机制变量，用来解释信息扩散与态度演化的形成链条。方法上，我们以真实传播结果来校准兴趣匹配、内容热度、时间衰减与随机探索这几类推荐参数。工程上，则形成「数据治理—参数校准—配置注入—在线仿真—结果归档」的完整平台闭环。一句话概括这个转向：推荐参数不再由研究者主观设定，而是由真实传播数据校准之后，再进入在线仿真。

# 05_三条脉络

接下来是国内外研究现状。已有工作大致沿三条脉络展开。第一条是规则 ABM 与传播动力学，比如 Bounded Confidence、SIR、Hawkes、元胞自动机，这类模型成本低、可解释，但弱在文本生成与个体行为解释。第二条是 LLM Agent 与混合仿真，像 Generative Agents、HiSim、FDE-LLM、GASim、TopoSim、APS，推动了画像、记忆、信念与混合架构。第三条是平台化系统与推荐机制，如 OASIS、GGBond、POSIM、PolicySim，已经开始纳入平台环境和推荐排序，但参数多依赖预设或离线调参。总体来看，研究基础已经比较充分，但「真实传播数据到推荐参数校准再到在线仿真注入」这条链条仍然不完整。

# 06_研究空白

把研究空白说得更具体一些。已有系统的常见做法有三种：要么没有显式推荐模块，靠邻居传播、时间线或随机曝光；要么有推荐模块，但用的是兴趣公式、hot-score、人工权重或离线调参；政策优化类工作则更关注干预效果本身。本课题要解决的，是把推荐评分拆解为可解释的维度，用真实传播结果拟合校准参数，再把校准后的参数写入 YAML 去驱动在线 Feed 排序。核心就是这一句：从主观预设，走向数据校准。

# 07_研究目标

第三部分，研究目标与创新点。总目标是设计并实现一个融合推荐机制校准的 MOSS 社交仿真平台，形成从真实数据到在线推演的可复现闭环。这个闭环包含四个环节：一是画像生成，从 user 和 post 数据生成稳定画像、行为画像和 Agent 运行画像；二是参数校准，拟合真实传播结果，校准推荐权重、时间衰减与层级影响参数；三是在线仿真，通过 Backend 与 Agent 双进程运行发帖、评论、点赞、转发等行为；四是闭环验证，用传播曲线、态度演化、互动分布和消融实验来评估有效性。

# 08_创新点

在目标之上，本课题有三个递进的创新点。创新一是推荐系统参数校准方法：把推荐抽象为兴趣匹配、内容热度、时间衰减、随机探索等可解释维度，用规则 ABM 拟合真实传播结果，通过 EM、Optuna、贝叶斯优化来校准权重，让参数由真实传播过程校准，而不是主观假设。创新二是离线校准到在线仿真的全流程闭环：把推荐权重、时间衰减、行为阈值和实验元数据写入统一的 YAML，由在线平台读取驱动推荐服务、Agent 决策与实验记录，实现参数自动流转，提升可复现性与跨领域复用。创新三是大模型与小模型的分层协同架构：高影响力核心用户由大模型驱动承担原创与复杂行为，普通用户由小模型完成低成本互动，在行为保真度、可解释性与运行效率之间取得平衡。

# 09_技术路线总览

进入第四部分，技术路线与方案。这张图是系统的闭环总览：真实数据经过画像生成，进入参数校准环节，由 EM 加 Optuna 完成；校准结果进入在线仿真，驱动 Feed 排序与 Agent 决策；最后通过 DTW、Pearson、MAE 以及消融实验做验证反馈，再回流到校准。整个系统由一个单一配置中枢 calibration_profile.yaml 串联，它把离线校准与在线推荐服务连接起来。

# 10_画像生成

下面分别介绍三个核心模块。第一个是用户画像生成。输入是 user 和 post 原始数据，包括发帖、互动、活跃时段、粉丝数，以及帖子与账号的影响力指标，还会筛选高质量证据帖。处理上采用五阶段 LLM 流水线：证据抽取、稳定画像、行为画像、Agent 画像压缩，最后是模拟初始状态。为了控制成本，我们按影响力分层：L4 到 L5 的高影响力用户走完整流水线，L1 到 L3 的用户采用 simple profile mode 与行为库。

# 11_ABM校准

第二个模块是 ABM 推荐参数校准，这也是本课题的方法核心。推荐的可见概率由四类分数加权得到：w_i 兴趣匹配、w_pop 内容热度、w_time 时间衰减、w_rand 随机探索。校准用的是 EMCalibrationEngine：E 步搜索每条内容的 p_base，M 步在 Dirichlet 约束下联合搜索推荐权重和 decay_lambda。最终输出就是 calibration_profile.yaml，可以供在线的 SocialRecSys.configure 直接注入。

# 12_在线模拟验证

第三个模块是在线模拟与验证。上面这张图是在线社交网络的系统架构。运行时由 main.py 启动 Backend 与 Agent 双进程：Backend 负责 Feed 推荐、内容管理、时间控制与持久化，Agent 通过决策循环执行发帖、评论、点赞、转发。验证方面，我们用功能完整性、参数一致性（DTW 与 Pearson）、MAE 与 MRE、随机种子方差以及参数消融等多个指标。验证的重点是确认：校准后的参数是否真的提升了传播曲线、态度演化与互动行为分布的拟合程度。

# 13_可行性

第五部分是可行性分析，四个方面都有基础。理论上，HiSim、FDE-LLM、OASIS 等研究已经证明混合仿真与平台化系统可行。方法上，EM、Optuna、贝叶斯优化与相关的奖励建模研究都可以迁移到推荐参数估计。数据与画像方面，用户画像生成和分层建模已有 Two-stage Profiling、TWICE 等研究支撑。工程上，FastAPI、SQLite、向量检索与 LangChain 等工具链足以支撑整个系统的实现。

# 15_总结

最后做个总结。本课题以推荐机制校准为核心，把真实传播数据治理、ABM 参数校准、大小模型分层仿真与多指标验证，连接为一个可复用的社交仿真平台闭环。预期带来三方面贡献：现实参照、机制解释力，以及跨议题的复用能力。
