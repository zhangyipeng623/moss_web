这张图展示平台的数据流转时序：离线与在线通过单一配置中枢 calibration_profile.yaml 实现单向贯通，而非误差反馈循环。离线阶段从原始用户与帖子数据出发，经五阶段画像生成流水线产出 portraits 目录下的画像 JSON；ABM 参数校准（EM 与 Optuna）以真实传播观测数据（repost / view 比率）为拟合目标，反推得到四维推荐权重、衰减系数与阈值等校准产物，统一写入配置中枢。在线阶段从配置中枢读取参数，注入 SocialRecSys 的 Feed 排序；画像 JSON 则经 agents.csv 填充为 Agent 人格模板——两条接口并行汇入在线阶段，驱动 Agent 模拟运行，结果归档到 runs 目录用于指标评估与消融实验。需要强调的是，离线校准是一次性过程，其误差信号来自真实历史观测而非在线模拟结果；在线运行产物只落到 runs 归档，是流程终点，不回流到离线重新校准。若需迭代，由人工修改原始数据后重跑离线流水线触发，并非在线误差自动驱动。
