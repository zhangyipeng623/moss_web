# AGENTS.md

## Commands

```bash
uv sync                                              # install Python deps
python main.py --config <path/to/calibration_profile.yaml>   # run simulation (YAML, not JSON!)
uv run python -m analysis.run_analysis portrait --data-path <dir> --user-name <name> [--batch]
uv run python -m analysis.run_analysis recommender --data-file <xlsx> --portraits-dir <dir>
uv run python -m analysis.run_analysis retier --portraits-dir <dir>
cd frontend && npm run dev                           # Vite dev (proxies /api → :8000)
cd frontend && npm run build                         # tsc -b + vite build → backend/static/
cd frontend && npm run lint                          # ESLint
```

No test framework, no type checker (Python), no formatter configured. `test.py` is gitignored.

## Config format: YAML, not JSON

`main.py --config` is **required** and expects a **YAML** file (`CalibrationProfile`), not JSON. The old `ExperimentConfig` JSON path (`configs/experiments/default.json`) is vestigial — `main.py` never loads it directly. The YAML is auto-generated by the `recommender` command into `<portraits_dir>/calibration_profile.yaml`.

The YAML has 5 sections: `meta`, `experiment`, `recommender`, `embedding`, `simulation`. `SocialRecSys.configure()` is called from `main()` to inject `recommender` and `embedding` sections into the backend, overriding hardcoded class-level constants.

## Env loading

- `main.py` loads `.env` from project root via `dotenv.load_dotenv()` at module level.
- `run_analysis.py` tries `analysis/.env` first, then falls back to project-root `.env`.
- Required: `API_KEY`, `BASE_URL` (LLM service). Optional: `BACKEND_URL` (default `127.0.0.1`), `BACKEND_PORT` (default `8000`).

## Architecture

`main.py` uses `multiprocessing` to start two processes:
1. **Backend** — FastAPI on port 8000, serves SPA from `backend/static/`
2. **Agent** — `AgentGraph` loop: LangChain `ChatOpenAI` agents call Backend API

Agent waits ≤30s for `GET /api/v1/health` before starting. Each run archives into `runs/<timestamp>/` with `moss.db`, `backend.log`, `agent.log`, `experiment.snapshot.json`.

## Frontend build is mandatory before running

Backend serves SPA from `backend/static/`. Vite `outDir` is `../backend/static` with `emptyOutDir: true`. Run `npm run build` (which does `tsc -b && vite build`) before starting `main.py`. Dev server proxies `/api` → `localhost:8000`.

## Offline analysis pipeline order

1. `portrait --batch` → generates per-user JSON in `analysis_outputs/portraits/` with `influence_tier` (L4/L5, P84 split)
2. `recommender --data-file <xlsx> --portraits-dir <dir>` → infers weights + auto-generates `calibration_profile.yaml` in the portraits dir
3. Use the generated YAML to run `main.py --config <calibration_profile.yaml>`

## Recommender weight mapping (from YAML → backend constants)

| YAML key | SocialRecSys class var |
|----------|----------------------|
| `recommender.weights.w_interest` | `W_BELIEF` |
| `recommender.weights.w_popularity` | `W_POP` |
| `recommender.weights.w_time` | `W_CHRONO` |
| `recommender.weights.w_random` | `W_RAND` |
| `recommender.decay_lambda` | `DECAY_LAMBDA` |
| `recommender.tier_weight` | `TIER_WEIGHT` |
| `embedding.model_name` | `_embedding_model_name` |

## Agent profiles

CSV-driven via `agents_csv` in experiment config. Columns: `username`, `name`, `bio`, `profile_mode` (`default`/`custom`/`simple`), `profile_path` (path to portrait JSON), `profile_text`, etc. `profile_mode=default` uses structured JSON from `analysis_outputs/portraits/`.

## Platform quirks

- `sqlite-vec` requires native extension wheel — may fail on unsupported platforms/architectures.
- `SentenceTransformer("all-MiniLM-L6-v2")` is lazy-loaded on first feed request, but `configure()` may override the model name via `_embedding_model_name` (note: the `__init__` still hardcodes `"all-MiniLM-L6-v2"` for the actual `SentenceTransformer()` call regardless of what `configure()` sets — this is likely a bug).
