# 闭环重构方案：用户画像 → 推荐参数反推 → 模拟运行

## Context

当前系统三阶段各自独立运行，存在多个断点导致校准结果无法有效作用于实际模拟。本次重构目标：打通"画像生成 → 推荐参数反推 → 模拟运行"的完整闭环。

核心变更：
1. 画像分级从 3-5 改为 4-5（Rogers 5 级框架）
2. ABM 时间衰减改为指数形式，decay_lambda 纳入 Optuna 搜索
3. POP 保持单维度，乘以 tier 预设权重（L1-L5 不同系数）
4. 引入 Per-Batch Min-Max 归一化，解决多维度量纲不统一问题
5. L1-L3 用户从预设库抽样，使用简化 prompt
6. Backend 推荐服务对齐 ABM 的 5 个打分维度
7. **新增 `calibration_profile.yaml`**：将离线校准结果 + 在线模拟默认参数写入画像目录下的统一配置文件，替代当前硬编码常量手动同步

| 原则 | 说明 |

| **唯一配置源（Single Config File）** | 不再有 experiment.json，所有模拟启动参数从 YAML 读取 |

### 2. `analysis/recommender_parameter_inference.py` — ABM 引擎重构

**`VectorizedABMEngine.run_simulation`**：
- 时间衰减：`1/(1+2*dt)` → `exp(-decay_lambda * dt)`
- POP 保持单维度，引入 tier 预设权重：
  `engage_norm = log1p(curr_count)/log1p(N) * TIER_WEIGHT[author_tier]`
- 权重参数 4 维 + decay_lambda（共 5 个校准参数），约束 `w_i + w_pop + w_time + w_rand = 1.0`
- **Per-Batch Min-Max 归一化**：每步对所有活跃帖×在线用户计算原始分数后，逐维度做 Min-Max 归一化到 [0,1]，再加权求和
- 全量可见性公式：
  ```
  raw_interest = cos_sim(user_embed, story_embed)
  raw_pop      = log1p(curr_count)/log1p(N) * TIER_WEIGHT[author_tier]
  raw_time     = exp(-decay_lambda * dt)
  raw_rand     = random()

  score = w_i     * norm(raw_interest)
        + w_pop   * norm(raw_pop)
        + w_time  * norm(raw_time)
        + w_rand  * norm(raw_rand)
  ```
  其中 `norm()` 为当前候选集内的 Min-Max 归一化
- TIER_WEIGHT 预设常量（不参与校准）：
  ```python
  TIER_WEIGHT = {1: 0.4, 2: 0.7, 3: 1.0, 4: 1.5, 5: 2.0}
  ```

**`PopulationSynthesizer`**：
- `target_size` 默认按 `seeds / 0.16` 自动计算
- 新增 `tier_counts` 参数，按 Rogers 比例生成 L1-L3 扩展用户
- 扩展用户的 `p_online` 按 tier 查表（L1=0.003, L2=0.01, L3=0.04）
- 种子的 `p_online` 按 tier 查表（L4=0.10, L5=0.20）

**`EMCalibrationEngine`**：
- Optuna 搜索空间 5 维（`w_i`, `w_pop`, `w_time`, `w_rand`, `decay_lambda`）
- 4 个权重使用 Dirichlet 分布采样，自动满足 `sum = 1.0` 约束
- `decay_lambda` 搜索范围 `log-uniform [0.01, 3.0]`（对应半衰期 15min ~ 69h）
- tier_weight 不参与搜索，作为预设常量传入

**`_portrait_to_persona`**：

### 6. `backend/services/social_recsys.py` — 推荐分数对齐 + 从 YAML 读取配置

**分数计算（两步法）**：

Step 1 — 对候选池内每个帖子计算原始分数：
```python
raw_interest = cos_sim(user_embed, post_embed)
raw_pop      = (log1p(weighted_interactions) / 10) * TIER_WEIGHT[author_tier]
raw_time     = exp(-DECAY_LAMBDA * delta_hours)
raw_rand     = random()
```

Step 2 — 逐维度 Min-Max 归一化后加权：
```python
score = (W_BELIEF * norm(raw_interest, all_raw_interest)
         + W_POP   * norm(raw_pop, all_raw_pop)
         + W_CHRONO * norm(raw_time, all_raw_time)
         + W_RAND  * norm(raw_rand, all_raw_rand))
```

- `norm(val, all_vals)` = `(val - min(all_vals)) / (max(all_vals) - min(all_vals) + 1e-8)`
- `TIER_WEIGHT` 与 ABM 端一致：`{1: 0.4, 2: 0.7, 3: 1.0, 4: 1.5, 5: 2.0}`
- 权重约束：`W_BELIEF + W_POP + W_CHRONO + W_RAND = 1.0`

**配置来源变更**：不再使用模块顶部硬编码常量，改为从 `calibration_profile.yaml` 读取。

## 分数归一化方案（Per-Batch Min-Max Normalization）

### 问题

4 个打分维度的原始值处于不同的量纲和分布：

| 维度 | 原始范围 | 问题 |
|------|---------|------|
| interest_match | [0, 1] (cosine) | 分布集中在高值区，方差小 |
| engage_norm × tier_weight | [0, ~5] (取决于 cascade 规模) | 量纲远大于其他维度，容易主导排序 |
| time_decay | (0, 1] | 稳态后大部分帖子接近 0 |
| random | [0, 1] | 均匀分布 |

如果不做归一化，`w_pop` 会被 Optuna 推到极小值来补偿 engage_norm 的大尺度，导致权重不可解释。

### 方案：Per-Batch Min-Max Normalization

参照 LinkedIn LiRank、快手 EMER 等工业实践，对**每个时间步（ABM）/ 每次请求（Backend）的候选集**，逐维度做 Min-Max 归一化：

```
normalize(x_i) = (x_i - x_min) / (x_max - x_min + ε)
```

归一化后所有维度均在 [0, 1]，权重可以直接迁移。

### 归一化后的评分公式

ABM 和 Backend 统一使用两步计算：

**Step 1 — 计算原始分数（候选集内所有帖子 × 所有用户）**：
```
raw_interest[i] = cos_sim(user_embed, post_embed)        # [0, 1]
raw_pop[i]      = log1p(curr_count) / log1p(N) * TIER_WEIGHT[author_tier]  # [0, ~5]
raw_time[i]     = exp(-lambda * delta_t)                   # (0, 1]
raw_rand[i]     = random()                                 # [0, 1]
```

**Step 2 — Per-Batch Min-Max 归一化后加权**：
```
score[i] = w_i     * norm(raw_interest[i])
         + w_pop   * norm(raw_pop[i])
         + w_time  * norm(raw_time[i])
         + w_rand  * norm(raw_rand[i])
```

其中 `norm()` 是对当前候选集内该维度的 Min-Max 归一化。当候选集中该维度全部相同（max==min）时，`norm(x) = 0.5`。

### 权重约束

归一化后，所有维度在 [0, 1] 且量纲统一，可以采用凸组合约束：
```
w_i + w_pop + w_time + w_rand = 1.0
每个 w ∈ [0, 1]
```
Optuna 搜索时使用 Dirichlet 分布采样，保证约束自动满足。

### 为什么选 Min-Max 而非其他

| 方法 | 不适合的原因 |
|------|------------|
| Z-score | 需要维护全局 μ/σ，动态系统中会漂移 |
| Softmax | 维度内分数变成概率分布，改变了相对距离 |
| Rank 归一化 | 信息损失太大（只保留序关系，丢失距离） |
| Gauss Rank | 实现复杂，调试困难 |

Min-Max 是最简单、最透明的方案，且对于这个 4 维度线性加权的场景完全够用。

## 数据流对账（闭环验证）

| 信号 | ABM 校准端 | Backend 运行端 | 权重常量 |
|------|-----------|---------------|---------|
| 兴趣 | `w_i × norm(cos_sim)` | `W_BELIEF × norm(cos_sim)` | W_BELIEF ← w_i |
| 热度×层级 | `w_pop × norm(engage_norm × TW)` | `W_POP × norm(engage_norm × TW)` | W_POP ← w_pop |
| 时间衰减 | `w_time × norm(exp(-λ·dt))` | `W_CHRONO × norm(exp(-λ·dt))` | W_CHRONO ← w_time, DECAY_LAMBDA ← decay_lambda |
| 探索 | `w_rand × norm(random())` | `W_RAND × norm(random())` | W_RAND ← w_rand |

TIER_WEIGHT (TW) 为预设常量，ABM 与 Backend 共用同一张表：`{1: 0.4, 2: 0.7, 3: 1.0, 4: 1.5, 5: 2.0}`

权重约束：`w_i + w_pop + w_time + w_rand = 1.0`

**配置传递路径**（新）：

```
run_analysis recommender
  → 反推 best_weights + decay_lambda
  → 写入 <portraits_dir>/calibration_profile.yaml
  → main.py 启动时读取 YAML
  → SocialRecSys.configure(calibration) 注入
  → Agent 模拟使用校准参数
```

不再需要手动复制粘贴权重常量。

## CalibrationProfile Pydantic 模型（`core/calibration_profile.py`）

新增文件，定义 YAML 的反序列化模型。包含 YAML 全部 5 个段（meta / experiment / recommender / embedding / simulation）的 Pydantic 类，并提供 `to_experiment_config()` 方法将 YAML 的 `experiment` 段转换为 `ExperimentConfig`。

```python
from pydantic import BaseModel, Field
from typing import Dict, Optional, List, Any
from core.experiment_config import ExperimentConfig, LLMConfig, SystemTimeExperimentConfig, RuntimeExperimentConfig, PortraitConfig


class ExperimentYamlConfig(BaseModel):
    """YAML 中 experiment 段的模型（映射原 experiment.json 全部字段）"""
    name: str = "默认实验"
    description: str = ""
    global_event: str = ""
    llm: LLMConfig = Field(default_factory=lambda: LLMConfig(model="gpt-4o"))
    agents_csv: str = "configs/experiments/default_agents.csv"
    portrait: PortraitConfig = Field(default_factory=PortraitConfig)
    system_time: SystemTimeExperimentConfig = Field(
        default_factory=lambda: SystemTimeExperimentConfig(start_time="2026-05-17T12:00:00")
    )
    runtime: RuntimeExperimentConfig = Field(default_factory=RuntimeExperimentConfig)


class RecommenderWeights(BaseModel):
    w_interest: float = Field(default=0.35, ge=0.0, le=1.0)
    w_popularity: float = Field(default=0.25, ge=0.0, le=1.0)
    w_time: float = Field(default=0.25, ge=0.0, le=1.0)
    w_random: float = Field(default=0.15, ge=0.0, le=1.0)


class RecommenderConfig(BaseModel):
    weights: RecommenderWeights
    decay_lambda: float = Field(default=0.5, gt=0.0)
    tier_weight: Dict[int, float] = Field(
        default_factory=lambda: {1: 0.4, 2: 0.7, 3: 1.0, 4: 1.5, 5: 2.0}
    )
    calibrated_p_base: Dict[str, Any] = Field(default_factory=dict)
    fit_diagnostics: Dict[str, Any] = Field(default_factory=dict)


class EmbeddingConfig(BaseModel):
    model_name: str = "BAAI/bge-m3"
    normalize_embeddings: bool = True


class SimulationDefaults(BaseModel):
    p_online: Dict[int, float] = Field(
        default_factory=lambda: {1: 0.003, 2: 0.01, 3: 0.04, 4: 0.10, 5: 0.20}
    )
    belief_update: Dict[str, float] = Field(
        default_factory=lambda: {"backfire_mu": 0.4, "backfire_k": 10.0, "learning_rate": 0.1}
    )
    content_filter: Dict[str, float] = Field(
        default_factory=lambda: {"min_scaled_target": 5, "anchor_percentile": 0.8}
    )
    feed: Dict[str, int] = Field(
        default_factory=lambda: {"candidate_limit": 100, "feed_limit": 5}
    )
    memory: Dict[str, int] = Field(
        default_factory=lambda: {"short_term_max_rounds": 3, "short_term_max_posts": 3, "event_max_size": 50, "step_retry_limit": 3}
    )


class CalibrationProfile(BaseModel):
    meta: Dict[str, Any]
    experiment: ExperimentYamlConfig = Field(default_factory=ExperimentYamlConfig)
    recommender: RecommenderConfig
    embedding: EmbeddingConfig
    simulation: SimulationDefaults = Field(default_factory=SimulationDefaults)

    def to_experiment_config(self) -> ExperimentConfig:
        """将 YAML 的 experiment 段转换为 ExperimentConfig（替代原 experiment.json 加载）。"""
        exp = self.experiment
        return ExperimentConfig(
            name=exp.name,
            description=exp.description,
            global_event=exp.global_event,
            llm=exp.llm,
            system_time=exp.system_time,
            runtime=exp.runtime,
            portrait=exp.portrait,
            agents_csv=exp.agents_csv,
        )
```
