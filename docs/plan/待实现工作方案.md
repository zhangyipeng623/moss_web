## A. 参数一致性收尾（最高优先）

### A-1 时间单位对齐：hours_per_step 从 time_scale 单一推导（R1）✅

**问题**：ABM 引擎 `hours_per_step` 恒为默认 1.0，实例化处未从 `time_scale` 推导（`recommender_parameter_inference.py:1166-1174`）。虽然当前定每步 1 小时时 `time_scale/3600 = 1.0` 恰好等于默认值，但**必须显式接线**——否则改 `time_scale`（如做 20 分钟高分辨率补充实验）时 ABM 不跟，两侧半衰期又不一致。

**关键结论（务必记牢，别搞反）**：dt 两侧统一到**小时**后，`decay_lambda` 量纲是"每小时"，**改 time_scale 不需要重算 λ**——λ 与步长解耦。只有当 dt 留成"每步"单位时才需要跟着 time_scale 重算 λ，那条路不走。

**修法**：
```python
# ABM 引擎实例化处（recommender_parameter_inference.py:1166-1174 附近）
hours_per_step = time_scale / 3600.0   # time_scale 从实验配置读，单一真值源
engine = VectorizedABMEngine(..., hours_per_step=hours_per_step)
```
`time_scale` 需从校准命令能拿到（可作为 recommender CLI 参数或从配置读，默认 3600）。

**验证**：ABM 一步的衰减 `exp(-λ×hours_per_step)` 与在线一步 `exp(-λ×time_scale/3600)` 相等。

### A-2 pop 维度尺度越界（R3）✅（选归一化方案）

**问题**：`raw_pop_scalar = popularity_base × avg_tier_coeff`，tier 系数最高 2.0（tier 5），使 pop 维可达 ~2.0，而 interest/time/rand 都在 [0,1]（`recommender_parameter_inference.py:610-612`；在线 `popularity_base` 因加权互动数可能 > 注册用户数也会 >1）。四维未完全同尺度，`w_pop` 与其他权重不完全可比，削弱"可解释权重"这一核心主张。

**两个选择（二选一）**：
- **(推荐) tier 系数归一化**：`TIER_WEIGHT` 除以 `max(TIER_WEIGHT.values())`，使 tier 系数 ∈ (0,1]，pop 维回到 [0,1]。两侧 scoring.py 同步。
- **论文声明**：明确 pop 维尺度上界为 2、其余为 1，权重解释时按此换算。

若选归一化，注意在线 `popularity_base` 的 `reach/N` 也要保证 ≤1（reach 用去重人数而非加权互动计数，或额外 clip）。

## B. 性能与健壮性

### B-1 批量画像建索引（R4 / 原画像问题3）✅
**问题**：批量画像只把整表 I/O 提到循环外读一次，但 `_build_portrait_source_from_rows`（`run_analysis.py:860-876`）循环内仍对 user_rows/post_rows **逐用户线性扫全表 + 逐行 normalize**，CPU 侧仍 O(N×表大小)。
**修法**：批量入口一次性建索引，循环内 O(1) 查表：
```python
from collections import defaultdict
posts_by_user = defaultdict(list)
for row in post_rows:
    posts_by_user[_normalize_username(row.get("用户名"))].append(row)
user_by_name = {_normalize_username(r.get("用户名")): r for r in user_rows}
# _build_portrait_source_from_rows 改为接收 user_row + 该用户的 post_rows 子集
```

### B-2 M-step 子集噪声（R5）✅
**问题**：story 数 >20 时每个 trial 用 `self._rng.choice` 抽**不同的** 20 条（`recommender_parameter_inference.py:914-922`），不同 trial 在不同内容子集上评 loss，给 Optuna 目标注入子集噪声。
**修法**：在 study 开始前**固定一次**抽样集，贯穿整个 study 所有 trial；或增大 `n_repeats` 稀释。当前代表性内容常 ≤20 走全量分支时不受影响，story 多时需处理。

### B-3 belief_text 口径统一（R6）✅
**问题**：在线用 `identity_summary + interest_summary`（`agent.py:159-162`），ABM 用户嵌入只用 `identity_summary`（`recommender_parameter_inference.py:1431`）。兴趣匹配的文本口径不一致。
**修法**：两侧统一（建议都用 `identity_summary + interest_summary`），改 ABM 侧 `_portrait_to_persona` 的嵌入文本拼接。

### B-4 已存在用户刷新 tier/belief_text（R7，边缘）✅
**问题**：`api.py:59-61` 用户已存在直接返回旧记录，不更新 tier/belief_text。每 run 用新 moss.db 时无影响，同库复用会残留旧值。
**修法**：login 命中已存在用户时，用最新 tier/belief_text UPDATE（或明确文档说明"每 run 必须新库"）。优先级最低。
