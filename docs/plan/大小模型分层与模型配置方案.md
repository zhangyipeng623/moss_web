# 大小模型分层与模型配置方案

> 状态：**方案已冻结，代码未实施**。本文固化「大模型核心用户 + 小模型普通用户」分层仿真的口径、模型选型、配置收口与落地改动清单。
> 关联：[[研究总览_创新点与验证]]（创新点 2）、[[闭环跑通修复总览]]（现状进度）、[[待实现工作方案]]

## 一、目标与背景

开题创新点 2 是「**大模型核心用户 + 小模型/规则普通用户的分层混合仿真**」，落点是「全大模型效果好，但大小模型分层效果差不多、成本很少」。

但当前代码**只分层了画像，没分层模型**：

- `main.py` 只创建**一个** `ChatOpenAI`（`main.py:143-157`）；
- `agent_graph.py:33/77` 把同一个 `llm` 传给**每一个** `MossAgent`；
- `agent.py:126` 所有 agent 的 `create_agent(self.llm, ...)` 都调它。

因此 `simple`（普通）用户只是画像模板更短（`SIMPLE_USER_TEMPLATE`，省了画像生成成本），**决策时仍和大模型用户共用同一个模型**。「大小模型分层」尚未落到 LLM 层，本方案补上这一环，并把模型配置收口进 `calibration_profile.yaml`。

底层是 **OpenAI 兼容协议**（`langchain_openai.ChatOpenAI` + 环境变量 `BASE_URL`/`API_KEY`），任何兼容端点（DeepSeek 官方 / 阿里 qwen / 本地 vLLM 等）都只是「改 `BASE_URL` + `model` 字符串」，协议一行不动。这天然支持大小模型各自独立端点。

## 二、分层口径：三层解耦

模型层、行为层、画像层是三个正交维度，**不绑定**：

```
┌─ 模型层（二元）──────────────────────────────┐
│  core = 核心用户  → 大模型                     │
│  mass = 普通用户  → 小模型                     │
└────────────────────────────────────────────┘
┌─ 行为/影响力层（5 档，Rogers 保留）────────────┐
│  tier 1..5 —— 只管"传多远 / 多活跃"，不管模型  │
└────────────────────────────────────────────┘
┌─ 画像层（两态，不新增轻量画像）────────────────┐
│  default = 5 阶段真实画像（只有 core 跑）       │
│  simple  = 纯 bio + tier 预设（mass 用）       │
└────────────────────────────────────────────┘
```

### 完整映射表（agents.csv 语义）

| 层 | tier | 画像来源 | 驱动模型 | 活跃度行为（`TIER_BEHAVIOR`） |
|---|---|---|---|---|
| core | 5 Innovators | default 真实画像（5 阶段 LLM） | 大模型 | 重度活跃/意见领袖 |
| core | 4 Early Adopters | default 真实画像 | 大模型 | 比较活跃/选择性互动 |
| mass | 3 Early Majority | simple（纯 bio + 预设） | 小模型 | 定期浏览/感兴趣才互动 |
| mass | 2 Late Majority | simple（纯 bio + 预设） | 小模型 | 偶尔/极少发帖 |
| mass | 1 Laggards | simple（纯 bio + 预设） | 小模型 | 几乎潜水 |

### 关键决策

1. **5 档 tier 完整保留**，但只作为行为/影响力参数（`TIER_WEIGHT`、`p_online`、`TIER_BEHAVIOR`），与"用哪个模型"完全脱钩。不存在"五级各配一个模型"。
2. **mass 不跑轻量画像**，维持 `simple` 纯 bio + tier 预设。画像成本只花在 core（L4/L5）上，mass 画像成本 = 0，即创新点 2「画像生成成本分层」的落点。
3. **分流规则 = 按 `profile_mode`**：`default` → 大模型、`simple` → 小模型。这条切分线代码里已天然存在（`core/agent_profile_resolver.py:99-112`），不引入新的 tier 判断逻辑。
4. 批量画像已按 **P84 单阈值**自动把真实用户切成 L4/L5（`run_analysis.py`），L1-L3 本就是在 `agents.csv` 里手动配 simple 行。

## 三、模型选型结论

| 层 | 模型 | 底座 | 状态 |
|---|---|---|---|
| core（大模型） | DeepSeek flash 档 | OpenAI 兼容端点 | **具体 model id 待确认**，需在端点确认支持 function calling |
| mass（小模型） | Qwen2.5-7B-Instruct | 自部署 vLLM（`http://localhost:xxxx/v1`） | 硬件/量化待定；显卡不行则改走 API |

**选型第一门槛**（比 benchmark 重要）：小模型必须**稳定支持 function calling + 中文 + 合法 JSON 输出**，否则 `create_agent` + `StructuredTool` 的工具调用会崩。这也是自部署时 vLLM 必须配好 chat template（`--chat-template` 或 trust remote code）的原因。

**小模型 fallback**：显卡不行时，把 `llm_small.base_url` 从本地 vLLM 换成 qwen 官方兼容端点即可，代码不动——这正是 OpenAI 兼容协议的便利。

**大模型注意事项**：若经中转端点（如 OpenRouter）转发国产模型，不同 model id 的 tool calling 兼容性参差，需先用 1 个 core 用户跑通「发帖 + 评论 + 点赞」完整动作链，确认 JSON 不空转再上规模。

## 四、模型配置进 YAML

目标：**YAML 管模型选型与分层，.env 管密钥与端点**。

```yaml
experiment:
  llm:                              # 大模型 core（已有）
    model: deepseek/<flash-id>       # 换档只改这里
    timeout: 180
    api_key_env: API_KEY
    base_url_env: BASE_URL

  llm_small:                        # 小模型 mass（新增）；删掉整段 = 对照组
    model: Qwen2.5-7B-Instruct
    timeout: 180
    api_key_env: API_KEY_SMALL
    base_url_env: BASE_URL_SMALL
```

`.env` 只留：

```
BASE_URL=https://...                  # 大模型端点
API_KEY=sk-...
BASE_URL_SMALL=http://localhost:8001/v1   # 小模型 vLLM；显卡不行换成 qwen 官方端点
API_KEY_SMALL=                        # 本地 vLLM 留空
```

**关键设计**：`llm_small` 缺省为 `None`，运行时回退全员大模型。因此：

- 对照组（全员大模型）= YAML 不写 `llm_small`；
- 实验组（分层）= YAML 写 `llm_small`。

对照实验切换零成本。

## 五、安全红线

**API key 绝不能进 YAML。** 因为 `main.py:220` 会把 `calibration_profile.yaml` 完整快照进 `runs/<id>/experiment.snapshot.json` 归档——key 若进 YAML，等于每次实验都把密钥明文写进归档目录。所以 key 留 `.env`，YAML 只放 model 名 + 环境变量名（`api_key_env`/`base_url_env`）。`base_url` 不算敏感，放 `.env` 统一更干净。

## 六、对照实验设计（创新点 2 验证核心）

- **对照组 A**：全员大模型（mass 也强行用大模型，即不写 `llm_small`）；
- **实验组 B**：core 大模型 + mass 小模型；
- **两组固定**：同一批画像、同一随机种子、同一 `global_event`，只换 mass 的模型；
- **观察指标**：传播量分布（KS）、内容排序（Spearman）、成本（token 数/费用）。

分流伪代码（`agent_graph.py` `add_agent` 内）：

```python
selected_llm = (
    self.llm_small
    if (profile_mode == "simple" and self.llm_small is not None)
    else self.llm
)
agent = MossAgent(..., llm=selected_llm, ...)
```

> `moss_agent_client/agent.py` **不用改**——`MossAgent` 已接收独立 `llm` 参数（`__init__` 第 93 行），分流只需上游传对 llm。

## 八、实施顺序与验证

顺序：1 → 2 → 3 → 4 → 5（配置模型层 → 分流层 → 启动层 → 环境）。

验证：

1. `python3 -m py_compile` 四个 py 文件；
2. **对照组跑通**：YAML 不写 `llm_small` → 退化为全员大模型，行为与现状一致；
3. **实验组跑通**：写 `llm_small` → 建议在 `add_agent` 加一行日志打印每个 agent 用的 model，验证分流生效；
4. `llm_small.base_url` 从本地 vLLM 换成 qwen 官方端点，确认只需改 `.env` 一处。

## 九、已定决策 / 待定项

**已定**：

- 模型层二元（core/mass）、行为层 5 档、画像层两态，三者解耦；
- 分流规则按 `profile_mode`；
- `llm_small` 缺省 None → 回退全员大模型；
- key 不进 YAML（快照归档风险）。

**待定**：

- 大模型 DeepSeek flash 档的确切 model id（需在端点确认 function calling 支持）；
- 小模型自部署的硬件/显存与量化方案（用户后续自行解决）。
