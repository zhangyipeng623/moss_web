MOSS 社交网络模拟系统

技术逻辑与学术参考  |  日期：2026-05-17  |  分支：feat/recsys  |  版本：v2 重构版（calibration_profile.yaml 配置注入 + Per-Batch Min-Max 归一化 + 指数衰减）

概述

MOSS 在线模拟系统是一个基于 LLM Agent 的社交媒体推演平台。系统启动两个独立进程——Backend（FastAPI 推荐服务）和 Agent（LangChain 决策循环）——Agent 通过调用 Backend API 执行发帖、评论、点赞、转发、引用等社交动作， Backend 使用校准后的推荐算法（SocialRecSys）为每个 Agent 提供个性化 Feed。

v2 重构版核心升级：通过 calibration_profile.yaml 统一配置入口，SocialRecSys.configure() 注入离线校准参数，Per-Batch Min-Max 归一化 + 指数时间衰减统一离线 ABM 与在线 Feed 的评分公式，三种 profile_mode 支持不同画像精度的 Agent。

1. 系统架构与进程模型

1.1 双进程架构

main.py 通过 multiprocessing.Process 启动两个独立进程：

main() 主进程 → Backend 进程 (FastAPI :8000) → Agent 进程 (AgentGraph)
进程职责关键技术
Backend REST API 服务（Feed 推荐、内容管理、用户管理、时间控制）、静态资源托管（前端 SPA）、SQLite 数据持久化 FastAPI + Uvicorn + sqlite-vec + SentenceTransformer
Agent 遍历已配置 Agent，每个 Agent 通过 LangChain LLM 决策，调用 Backend API 执行社交动作，循环往复 LangChain ChatOpenAI + RemotePlatform + MemoryManager

Backend 进程先启动，主进程通过 /api/v1/health 健康检查（最多等待 30 秒）确认就绪后，才启动 Agent 进程。

1.2 目录结构

目录职责
analysis/离线工具：用户画像生成（多阶段 LLM 流水线）、推荐参数反推（ABM/EM）、影响力重分级
backend/FastAPI 应用：REST 路由、DAO（SQLite + sqlite-vec 向量存储）、推荐服务、时间服务
moss_agent_client/Agent 决策循环、平台 API 封装（RemotePlatform）、记忆系统、提示词构建
core/实验配置加载（ExperimentConfig + CalibrationProfile Pydantic 模型）、运行上下文归档、Agent 画像解析
frontend/React 19 + Vite + Tailwind v4 单页应用；构建产物输出到 backend/static/
configs/experiments/calibration_profile.yaml + agents.csv 批量 Agent 配置

2. 启动流程与配置注入

2.1 启动命令

python main.py --config configs/experiments/calibration_profile.yaml

--config 现在是必需参数，指向 calibration_profile.yaml（不再是传统的 experiment JSON）。

2.2 配置加载链路

main() 中的启动流程（顺序执行）：

  1. 加载 YAML：yaml.safe_load(config_path) → CalibrationProfile.model_validate()
  2. 生成实验配置：calibration.to_experiment_config() → ExperimentConfig（含 LLM、时间、运行时、Agent 等配置）
  3. 注入推荐参数：SocialRecSys.configure(calibration.recommender, calibration.embedding) 将校准权重写入类级别属性
  4. 创建运行上下文：RunContext（时间戳运行目录、日志路径、配置快照）
  5. 启动 Backend → 等待健康检查 → 启动 Agent

2.3 SocialRecSys.configure() 注入机制

backend/services/social_recsys.py 中定义 classmethod：

@classmethod def configure(cls, recommender_config, embedding_config) -> None: cls.W_BELIEF = recommender_config.weights.w_interest cls.W_POP = recommender_config.weights.w_popularity cls.W_CHRONO = recommender_config.weights.w_time cls.W_RAND = recommender_config.weights.w_random cls.DECAY_LAMBDA = recommender_config.decay_lambda cls.TIER_WEIGHT = dict(recommender_config.tier_weight) cls._embedding_model_name = embedding_config.model_name

这是类级别注入——修改后所有后续 Feed 请求自动使用新参数，无需重启或重新实例化。

3. Agent 决策循环

3.1 MossAgent 初始化

MossAgent.__init__（moss_agent_client/agent.py）接收 profile_mode 参数：

  • default 模式：通过 agent_profile_resolver 解析画像 JSON → 填充 FIXED_USER_INFO_TEMPLATE（9 字段）→ 构建 StaticContext。任何字段缺失抛出 ValueError。
  • simple 模式：读取 bio + tier → 查找 TIER_BEHAVIOR[tier] → 填充 SIMPLE_USER_TEMPLATE（3 字段）→ 构建 StaticContext。未找到 tier 时回退到 tier=3。
  • custom 模式：使用用户提供的自定义模板字符串进行插值。

创建 LangChain agent（通过 create_agent()），绑定 ACTION_SPECS 工具列表，以及 MemoryManager（short_term_max_rounds=3, short_term_max_posts=3, event_max_size=50）。

3.2 决策步骤（step）

每个 Agent 每轮执行一次 step()：

  1. 获取环境快照：调用 Backend API 获取当前 Feed（GET /api/v1/feed）+ 当前模拟时间。首次尝试时冻结快照，重试时复用。
  2. 记忆检索：memory_manager.select_relevant_events() 提取与当前上下文相关的事件
  3. 构建 Prompt：PromptBuilder.build_runtime_context() 组合静态上下文 + 环境快照 + 记忆事件
  4. LLM 调用：self.agent.ainvoke()，解析输出 JSON（期望字段：final_output, state, event_memory），失败则回退到原始文本
  5. 执行动作：通过 RemotePlatform 调用 Backend API 执行决策结果（发帖/评论/点赞/转发/引用）
  6. 记录记忆：record_step() 写入短期记忆

每轮最多重试 3 次。

3.3 Agent 行为工具（ACTION_SPECS）

动作Backend API说明
发帖POST /api/v1/posts创建新帖子（含内容、话题标签等）
评论POST /api/v1/comments对帖子发表评论

4. Agent 记忆系统

4.1 MemoryManager 结构

记忆类型容量内容
短期记忆（rounds）3 轮最近几轮的动作和响应
短期记忆（posts）3 条最近互动过的帖子
事件记忆（events）50 条全局事件流，按相关性筛选后注入 Prompt

select_relevant_events() 根据当前上下文（关注话题、立场等）从事件记忆中筛选最相关的事件，避免超出 LLM 上下文窗口。

5.2 向量存储

使用 SentenceTransformer("all-MiniLM-L6-v2")（384 维嵌入）生成内容向量，通过 sqlite-vec 扩展存储在 posts_vec 虚拟表中。支持 MATCH ... ORDER BY distance 语义向量检索。

6. Feed 排序算法详解

6.1 候选生成

  1. 若用户有 bio：编码为向量 → sqlite-vec 向量搜索 MATCH ... ORDER BY distance LIMIT 100
  2. 若无 bio 或向量搜索失败：按 created_at DESC 时间倒序取 100 条

6.2 四维评分计算

对 100 条候选中的每条帖子，独立计算四个维度的原始分数：

维度符号计算公式
兴趣/立场亲和 s_similarity 1 / (1 + distance)（来自向量搜索），无 bio 时为 0
热度（Tier 加权） s_popularity_weighted clip(log1p(weighted_interactions) / 10, 0, 1) * TIER_WEIGHT[author_tier]
时间衰减 s_time exp(-DECAY_LAMBDA * delta_hours)
随机探索 s_random random.random()

6.3 两步法评分公式

第一步 — Per-Batch Min-Max 归一化：

对当前批次的 100 条候选，分别对四个维度的原始分数向量执行 Min-Max 归一化到 [0, 1]：

ni = min_max_norm(s_similarity_vec) np = min_max_norm(s_popularity_weighted_vec) nt = min_max_norm(s_time_vec) nr = min_max_norm(s_random_vec)

若某维度所有值相同（方差 < eps），则该维度的所有归一化值设为 0.5。

第二步 — 加权求和：

final_score = W_BELIEF * ni + W_POP * np + W_CHRONO * nt + W_RAND * nr

按 final_score 降序排列，取 top limit（默认 5）条返回，返回前移除内部 score 字段。

与离线 ABM 的一致性：在线 Feed 排序的两步法公式（Per-Batch Min-Max 归一化 + 加权求和）与离线 ABM 引擎的评分公式完全对齐，确保离线校准出的权重在在线环境中具有相同的数学语义。

6.4 users 表扩展字段

v2 重构在 users 表中新增了两个列：

tier INTEGER DEFAULT 3 -- Rogers 层级 (1-5) belief_text TEXT DEFAULT '' -- 信念文本描述

create_user()（backend/dao/users.py）签名扩展为：tier: int = 3, belief_text: Optional[str] = None。
