MOSS 社交模拟系统闭环重构

修改内容与参考文献报告  |  日期：2026-05-17  |  分支：feat/recsys

概述

本次重构旨在打通 MOSS 社交模拟系统中"用户画像生成 → 推荐系统参数反推 → Agent 模拟运行"三个阶段的完整闭环。 当前三个模块各自独立运行，存在多个断点（如权重不匹配、衰减函数不一致、层级分类不统一等），导致离线校准结果无法有效指导在线模拟。

核心思路是将推荐参数反推（ABM + EM 校准）中的打分维度、权重、归一化方式与后端推荐服务完全对齐，确保校准出的参数可以直接被模拟运行消费。

1. 用户影响力分级与种群合成

1.1 理论基础：Rogers 创新扩散理论与社交网络传播层级

核心参考：Rogers (1962) Diffusion of Innovations

Rogers 将创新采纳者分为五类，这一框架被广泛应用于社交网络用户影响力分级：

层级Rogers 分类全量人口占比系统角色p_online (活跃概率)
L5Innovators (创新者)2.5%种子用户：意见领袖，引领话题0.20
L4Early Adopters (早期采纳者)13.5%种子用户：关键传播节点0.10
L3Early Majority (早期大众)34%扩展用户：活跃传播者0.04
L2Late Majority (后期大众)34%扩展用户：间歇参与者0.01
L1Laggards (落后者)16%扩展用户：信息消费者/潜水者0.003
设计决策：种子用户 (L4+L5) 占全量用户的 16%（Rogers 前 16%），对应 P84 分位阈值。ABM 种群规模按 种子数 / 0.16 自动推导。

补充学术依据：

  • Barabási & Albert (1999) — 无标度网络 (Scale-Free Network)：社交网络的节点影响力遵循幂律分布 P(k) ~ k^(-γ)，γ ≈ 2–3。这解释了为什么少量 L5 用户可以拥有不成比例的高影响力。
  • Nielsen (2006) "1-9-90 法则" — 在线社区参与不平等：1% 重度贡献者、9% 轻度贡献者、90% 潜水者。与 Rogers 框架互补，用于校准 L1-L3 的 p_online 参数。
  • Sziklai et al. (2025) — IC 激活概率：在 ABM 仿真中，不同影响力层级的用户被信息激活的概率不同（0.95 / 0.75 / 0.50 / 0.25 / 0.05），为本系统的 p_online 表提供了参数参考。
  • Katz & Lazarsfeld — 两级传播理论 (Two-Step Flow)：信息从媒体流向意见领袖 (L5/L4)，再从意见领袖流向大众 (L1-L3)。这为 L4/L5 种子用户→L1-L3 扩展用户的种群合成策略提供了理论基础。
  • Granovetter (1973) — 弱连接优势 (Strength of Weak Ties)：L3/L4 级别的用户承担"桥接"不同社群的角色。因此在评分时需要区分跨社群互动能力。
  • Cha et al. (2010) — Twitter 影响力研究：高粉丝数 ≠ 高传播力，领域相关性是关键变量。支持在画像中加入话题/兴趣维度而非仅依赖粉丝数。
  • Christakis & Fowler (2007) — 三度影响力：影响力在社交网络中可传播至三度，说明 L4 用户在局部网络的穿透力可能超过 L5。支持不应将全部权重放在 L5 上。
  • Goldenberg (2001) — 级联效应 (Cascade)：信息引爆不仅取决于 L5，更取决于 L3-L4 的二次传播密度。这为 ABM 中的级联传播模型（Soft Backfire 等）提供了理论支持。

1.2 画像分级变更：从 L3-L5 三分位到 L4-L5 P84 阈值

旧方案：使用 P60/P90 两个分位数将种子用户分为 L3/L4/L5 三级。

新方案：

  • 移除 P60/P90 三分位，改为单个 P84 阈值（对应 Rogers 前 16%）
  • account_influence > P84 → L5 (Innovators, ~2.5% 全量)
  • 其余种子用户 → L4 (Early Adopters, ~13.5% 全量)
  • L1-L3 用户不从画像生成，而是从预设库抽样（简化 prompt 体系）

参考：P84 阈值的选择来自 Rogers 框架中 Innovators (2.5%) + Early Adopters (13.5%) = 前 16% 作为种子群体的学术共识。

2. ABM 引擎重构与 EM 校准

2.1 从旧版 Agent-Based Model 到新版 Vectorized ABM

参考实现：/Users/zhangyipeng/ZYPRoom/cuc/project/social_recommender_system/test.py (v8)

旧版（已废弃）：

  • BayesianAgent：每个 Agent 独立维护贝叶斯信念更新
  • SocialABM：基于优先连接图 (preferential attachment graph) 的网络拓扑
  • 随机采样方式进行参数搜索
  • 时间衰减：多项式 1/(1+2*dt)

新版：

  • VectorizedABMEngine：NumPy 向量化运算替代逐 Agent 循环，大幅提升仿真效率
  • PopulationSynthesizer：种子用户通过精英保留 + Zipf 影响力分布扩展为全量仿真种群
  • EMCalibrationEngine：E 步和 M 步均使用 Optuna 进行超参优化（替代旧版随机采样）
  • Soft Backfire 机制：信念更新引入回火效应 — 立场冲突时，极端用户有概率反而强化原有立场

核心学术参考：

  • Optuna (Akiba et al., KDD 2019) — 超参数优化框架，支持 TPE 采样器和 Pruning。本系统使用 Dirichlet 分布采样权重，自动满足凸组合约束。
  • EM 算法 (Dempster et al., 1977) — 期望最大化算法用于校准循环：E 步固定参数跑 ABM 观察传播结果，M 步用 Optuna 搜索使模拟结果逼近真实观测的最优参数。
  • Kernel PCA with RBF kernel (Schölkopf et al., 1998) — 将用户画像的多维嵌入投影到一维立场轴，用于计算用户间立场距离和兴趣匹配度。
  • SentenceTransformer + BAAI/bge-m3 — 中文文本嵌入模型，用于将用户画像文本和帖子内容编码为语义向量。

2.2 时间衰减函数变更

旧方案：多项式衰减 1 / (1 + 2 * dt)

新方案：指数衰减 exp(-decay_lambda * dt)

设计决策：指数衰减是传播学和推荐系统中最常用的时间衰减形式（如 Reddit、Hacker News 排名算法）。 decay_lambda 纳入 Optuna 搜索空间（log-uniform [0.01, 3.0]）， 对应半衰期约 15 分钟到 69 小时，覆盖从快速热点到慢速传播的全场景。

学术与工业参考：

  • Reddit Hot Ranking 使用对数时间衰减；Hacker News 使用指数重力衰减
  • 指数衰减形式 exp(-λt) 在数学上等价于放射性衰变模型，具有恒定的半衰期 ln(2)/λ，比多项式衰减更具可解释性

2.3 POP 维度设计：单维度 + Tier 预设权重

决策过程：最初考虑将 POP 拆分为"作者影响力"和"帖子热度"两个独立维度，但经讨论后确定保持单 POP 维度，通过 tier 预设权重来体现不同用户层级的传播能力差异。

TierTIER_WEIGHT含义
L52.0创新者内容具有最高传播潜力
L41.5早期采纳者内容具有较高传播潜力
L31.0早期大众作为基准线
L20.7后期大众传播力较弱
L10.4落后者传播力最弱
设计决策： TIER_WEIGHT 为预设常量（不参与 Optuna 搜索），ABM 和 Backend 共用同一张表。 这样做减少了校准参数数量（从 6 个减为 5 个），同时保证了 ABM 和 Backend 的完全对齐。 权重比例参照了 Rogers 框架中各层级的相对影响力差异。

3. 推荐系统多维度分数归一化

3.1 问题定义

系统的四个打分维度具有不同的量纲和分布，直接加权会导致：

  1. w_pop 被 Optuna 推到极小值来补偿 engage_norm 的大尺度，权重不可解释
  2. 跨场景权重无法迁移：离线校准的权重和在线运行的权重含义不同
  3. 跷跷板效应：某维度主导排序，其他维度失去作用

学术背景：多目标推荐排序中的分数归一化是推荐系统领域的经典问题。主流方法包括 Min-Max、Z-score、Rank Normalization、Reciprocal Rank Fusion (RRF) 等。

3.2 方案选择：Per-Batch Min-Max Normalization

参照以下工业实践和学术工作：

来源方法关键洞察
LinkedIn LiRank
(KDD 2024)		 Isotonic Calibration Layer + Batch Normalization 将校准层嵌入 DNN 内部共同训练（而非后处理），使用分桶 + 可学习非负权重保证单调性。DCNv2 模块中使用 Batch Normalization 防止训练发散。
快手 EMER
(2025)		 Rank Normalization + 自进化权重 为每个 item 计算候选集中归一化排名 (NormalizedRanks)，让模型感知相对位置而非绝对分数。自适应权重通过 Advantage Evaluator 动态计算各目标 loss 权重。
GoalRank
(2025)		 Group-Relative Normalization Batch 内计算均值和标准差做标准化：(r̂ - r̄_B) / σ_B。确保只有 batch 内相对效用差异驱动策略更新。
阿里 CMR
(KDD 2023)		 Hypernetwork 动态权重 使用 Hypernetwork 根据偏好权重向量动态生成重排模型参数，支持在线实时调整各目标权重。
Orbit
(IUI 2025)		 多目标 Ranker 设计框架 以目标为中心的交互式系统，支持实时探索多目标之间的 trade-off。
UMRE
(2025)		 无约束单调神经网络融合 使用 UMNN 学习严格单调的分数融合函数，引入 Pareto 最优策略自适应平衡竞争目标。
选择 Min-Max 的理由：
  • Z-score 需要维护全局 μ/σ，在动态系统中会漂移（ABM 每步候选集不同）
  • Softmax 改变了相对距离，维度内分数变成概率分布
  • Rank 归一化信息损失太大，只保留序关系而丢失距离
  • Gauss Rank 实现复杂，调试困难
  • Min-Max 最简单透明，对线性加权场景完全够用

3.3 归一化后的评分公式

两步法（ABM 和 Backend 统一）：

Step 1 — 计算原始分数（候选集内所有帖子 × 所有用户）： raw_interest[i] = cos_sim(user_embed, post_embed) # [0, 1] raw_pop[i] = log1p(curr_count)/log1p(N) * TIER_WEIGHT[author_tier] # [0, ~5] raw_time[i] = exp(-lambda * delta_t) # (0, 1] raw_rand[i] = random() # [0, 1] Step 2 — Per-Batch Min-Max 归一化后加权： score[i] = w_i * norm(raw_interest[i]) + w_pop * norm(raw_pop[i]) + w_time * norm(raw_time[i]) + w_rand * norm(raw_rand[i])

权重约束：w_i + w_pop + w_time + w_rand = 1.0（Dirichlet 分布采样）

边界处理：候选集中某维度全部相同（max==min）时，norm(x) = 0.5，避免除零。

4. 两套 Prompt 体系设计

4.1 设计动机

L4-L5 种子用户拥有完整的 LLM 生成画像（identity_summary, interest_summary, value_summary 等）， 应使用详细的画像 Prompt 来驱动精细化的行为模拟。 L1-L3 扩展用户从预设库中抽样，不经过 LLM 画像生成（成本和效率考虑）， 应使用简化的 Prompt 仅依赖 bio 和 tier 信息。

4.2 两套模板

详细模板 (profile_mode=default, L4-L5)：

你现在需要扮演 {name}，一个社交网络上的用户。 [身份概述] {identity_summary} [长期兴趣] {interest_summary} [价值与立场] {value_summary} [表达风格] {style_summary} [行为偏好] {behavior_summary} [互动规则] {interaction_summary} [表达要求] {speaking_rules_text} [行动要求] {action_rules_text} [避免事项] {avoidance_rules_text}

简化模板 (profile_mode=simple, L1-L3)：

你现在需要扮演 {name}，一个社交网络上的用户。 个人简介：{bio} {behavior_expectation} # behavior_expectation 按 tier 查表： # L3: "你是一个比较活跃的用户，会定期浏览信息流..." # L2: "你偶尔会浏览社交网络，很少主动发帖..." # L1: "你几乎不发帖，以浏览为主..."

学术参考：这种双层 Prompt 设计参考了 Agent-Based Modeling 中常见的 "detailed agent vs. lightweight agent" 范式——对关键节点使用高保真模型，对背景节点使用统计模型（Bonabeau, 2002; Macal & North, 2010）。

5. 闭环数据流对账

5.1 ABM 校准端 ↔ Backend 运行端 完全对齐

信号ABM 校准端Backend 运行端权重常量
兴趣匹配 w_i × norm(cos_sim) W_BELIEF × norm(cos_sim) W_BELIEF ← w_i
热度×层级 w_pop × norm(engage_norm × TW) W_POP × norm(engage_norm × TW) W_POP ← w_pop
时间衰减 w_time × norm(exp(-λ·dt)) W_CHRONO × norm(exp(-λ·dt)) W_CHRONO ← w_time
DECAY_LAMBDA ← decay_lambda
随机探索 w_rand × norm(random()) W_RAND × norm(random()) W_RAND ← w_rand

TIER_WEIGHT = {1: 0.4, 2: 0.7, 3: 1.0, 4: 1.5, 5: 2.0}（ABM 与 Backend 共用）

权重约束：w_i + w_pop + w_time + w_rand = 1.0

5.2 闭环使用工作流

画像生成 → 推荐参数反推 → 权重同步到 Backend → Agent 模拟运行
  1. 离线运行 run_analysis portrait，生成 L4/L5 种子用户画像
  2. 离线运行 run_analysis recommender，基于画像和观测数据反推 5 个校准参数
  3. 将 best_weights 手动同步到 backend/services/social_recsys.py 的权重常量
  4. 配置 agents.csv（L4/L5 用 default 模式 + 画像路径，L1-L3 用 simple 模式）
  5. 运行 main.py 启动完整模拟
