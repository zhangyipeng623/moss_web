MOSS ABM 模拟与推荐参数反推

基于向量化 ABM + Optuna EM 的推荐系统参数校准引擎（v2 重构版） |  2026-05-17  |  分支：feat/recsys

概述

ABM 推荐参数反推是 MOSS 系统的核心校准层。它通过 Agent-Based Model (ABM) 仿真信息传播过程， 使用 EM (Expectation-Maximization) 算法从真实社交媒体的内容传播观测数据中反推出最优推荐系统参数。 校准出的权重 (w_i, w_pop, w_time, w_rand) 和衰减系数 (decay_lambda) 通过自动生成的 calibration_profile.yaml 可直接注入在线 Backend 推荐服务。

v2 重构版核心升级：5 维参数联调（w_i, w_pop, w_time, w_rand, decay_lambda）、Per-Batch Min-Max 归一化消除量纲差异、Rogers 分层种群合成（种子/0.16 自动扩量）、Dirichlet 权重采样自动满足凸约束、指数时间衰减替代多项式衰减、TIER_WEIGHT 预设分层加权、校准完成后自动生成单一配置文件打通离线到在线链路。

核心文件：analysis/recommender_parameter_inference.py（约 1039 行，6 大模块），入口：analysis/run_analysis.py recommender

1. 语义处理模块（SemanticLoader）

1.1 立场轴投影（Kernel PCA）

从画像 JSON 中提取用户 value_anchors，使用 Kernel PCA (RBF kernel, 1 component) 将多维价值立场嵌入投影到一维立场轴：

stance_axis = KernelPCA(n_components=1, kernel="rbf").fit_transform(value_embeddings)

这一步将复杂的价值立场空间压缩为可计算的一维连续谱（-1 到 1），使得 ABM 仿真中可以直接计算用户间的立场距离和信念更新。

1.2 兴趣匹配

结合内容话题嵌入（来自 content_topics）与用户兴趣嵌入计算余弦相似度，作为 ABM 中 w_i（兴趣权重）对应的亲和度特征。

2. 种群合成模块（PopulationSynthesizer）

2.1 Rogers 比例自动扩量

PopulationSynthesizer 将种子用户（来自画像 JSON）扩展为全量仿真种群。 当 target_size 未指定时，自动计算：

target_size = max(int(len(seeds) / 0.16), len(seeds))

其中 0.16 对应 Rogers 理论中 Innovators + Early Adopters 的合计占比（约 16%）。 这意味着种子用户被假定为代表前 16% 的高影响力用户，系统自动推算全量种群规模。

2.2 合成策略

  • 精英保留：前 5% 高影响力种子用户原样保留
  • 大众合成：剩余 95% 通过重采样 + 高斯噪声 N(0, 0.1) 在 stance 维度上抖动生成
  • 影响力分布：合成用户的影响力服从 Zipf 分布，上限不超过精英群体中的最小影响力值
  • 默认仿真参数：num_agents=1500（当 target_size 显式指定时使用）

2.3 _portrait_to_persona 转换

从画像 JSON 提取 ABM 所需的最小字段集（recommender_parameter_inference.py 行 989-1038）：

3. 代表性内容筛选（StoryManager）

3.1 内容筛选逻辑

StoryManager 从内容观测 Excel 中筛选代表性内容用于校准：

  • 最小传播量过滤：min_scaled_target=5，过滤掉传播量过小的内容
  • 锚定百分位：anchor_percentile=0.80，以第 80 百分位的内容传播量作为归一化基准
  • scaled_target：将实际传播量按锚定值归一化，使不同量级的内容传播数据可比
  • 最多选取 20 条代表性内容参与 M-step 全局权重搜索

4. 向量化 ABM 引擎（VectorizedABMEngine）

4.1 核心仿真循环（run_simulation）

VectorizedABMEngine.run_simulation（行 496-592）执行向量化传播仿真，每步同时更新全部 Agent 状态：

四维评分公式：

scores = w_i * norm_interest + w_pop * raw_pop_scalar + w_time * raw_time_scalar + w_rand * norm_rand visible_prob = clip(scores, 0.0, 1.0)

各维度计算方式：

维度计算方式是否 Min-Max 归一化
interest (w_i) 用户-内容兴趣匹配度（基于语义嵌入余弦相似度） 是 Per-Batch Min-Max
popularity (w_pop) log1p(curr_count) / log1p(N) * avg_tier_coeff，其中 avg_tier_coeff 为当前已感染源的平均 TIER_WEIGHT 否（已是标量）
time (w_time) exp(-decay_lambda * max(dt, 0.0))，指数时间衰减，dt 为当前时间与最早感染源时间的差值 否（已是标量）
random (w_rand) 随机探索噪声 是 Per-Batch Min-Max

4.2 Per-Batch Min-Max 归一化

min_max_norm 函数（行 24-30）：

def min_max_norm(values: np.ndarray, eps: float = 1e-8) -> np.ndarray: v_min, v_max = values.min(), values.max() if v_max - v_min < eps: return np.full_like(values, 0.5) # 所有值相同时返回中位 return (values - v_min) / (v_max - v_min + eps)

在每批仿真步内，对 raw_interest 和 raw_rand 向量分别执行 Min-Max 归一化到 [0, 1]， 消除不同维度间的量纲差异，使四个维度的加权求和具有数学合理性。

关键设计：仅对 interest 和 random 做 Min-Max 归一化。time 和 pop 已经是 [0,1] 范围内的标量（指数衰减和 log 归一化自然保证），无需再做 Min-Max。

4.3 指数时间衰减

v2 重构版将时间衰减从多项式形式改为指数形式：

旧 (v1): time_weight = 1 / (1 + 2 * dt) 新 (v2): time_weight = exp(-decay_lambda * dt)

其中 decay_lambda 不再硬编码，而是纳入 Optuna 搜索空间（log-uniform [0.01, 3.0]）， 使系统能根据实际数据自动学习最优的信息衰减速率。

4.4 TIER_WEIGHT 分层加权

TIER_WEIGHT 为预设常量（不参与校准搜索）：

TIER_WEIGHT = {1: 0.4, 2: 0.7, 3: 1.0, 4: 1.5, 5: 2.0}

在 POP 维度计算中：avg_tier_coeff = mean(TIER_WEIGHT[t] for t in infected_source_tiers)， 使得高影响力用户（L4-L5）发布的内容在传播中获得更大 boost，低影响力用户（L1-L2）的内容传播力被压低。

4.5 Soft Backfire 信念更新

_update_beliefs（行 468-494）实现了基于认知失调理论的 Soft Backfire 机制：

  • 当目标与源立场符号相反（diff_prod < 0，即立场冲突），计算 backfire 概率：
    p_backfire = 1 / (1 + exp(-backfire_k * (|S_tgt| - backfire_mu)))
    默认参数：backfire_mu=0.4, backfire_k=10.0
  • 若 backfire 触发，信念更新方向反转（direction *= -1），极端用户反而强化原有立场
  • 无论是否触发 backfire，更新公式为：
    new_S = clip(S_tgt + learning_rate * direction, -1.0, 1.0)
    默认 learning_rate=0.1
理论基础：Soft Backfire 模拟了社交媒体上的"逆火效应"——当极端立场用户接触到对立观点时，有概率不是被说服，而是更加坚定原有立场。这比简单的线性信念更新更贴近真实社交网络的舆论动力学。

4.6 行为门控

即使内容可见（visible_prob），Agent 是否实际执行转发动作还经过一个逻辑门控：

p_action = 1 / (1 + exp(-(base_logit + alpha * |S|^2)))

立场越极端（|S| 越大），转发概率越高——模拟了极端内容更易被传播的社交媒体特征。

5. EM 校准引擎（EMCalibrationEngine）

5.1 EM 算法框架

EMCalibrationEngine 通过 3 轮 EM 迭代联合优化内容级参数和全局权重：

E 步（Expectation）— 校准每条内容的 p_base：

  • 对每条代表性内容，使用 Optuna（20 次试验）搜索最优 p_base
  • 每次试验运行 5 次仿真，取传播率的均值与真实 repost/view 比率比较
  • 目标：最小化仿真传播率与真实传播率的相对误差
  • E 步不搜索 decay_lambda（使用当前 M 步产出的值）

M 步（Maximization）— 搜索全局权重：

  • 5 维搜索空间：alpha_param (0.5–5.0) + decay_lambda (0.01–3.0, log-uniform)
  • Dirichlet 采样：Optuna 搜索 alpha_param 控制 Dirichlet 分布的集中度， 从 Dirichlet(alpha_param) 采样 4 维向量作为 (w_i, w_pop, w_time, w_rand)，自动满足 sum=1 和 ≥0 约束
  • 每次试验选取最多 20 条代表性内容，每条运行 3 次仿真，最小化平均相对误差
  • 50 次 Optuna 试验后，用最优 alpha_param 确定性重采样（seed=0）得到最终 best_weights

5.2 初始值与收敛

参数初始值搜索方式

w_pop (热度)0.25M 步 Dirichlet 采样

6. 编排器与 calibration_profile.yaml 生成

6.1 编排器入口

加载画像 JSON → SemanticLoader 语义处理 → PopulationSynthesizer 种群合成 → StoryManager 内容筛选 → EM 校准 → 生成 calibration_profile.yaml

CLI 参数：

uv run python -m analysis.run_analysis recommender \ --data-file <内容观测Excel> \ --portraits-dir <画像目录> \ [--embedding-model <模型名>] \ [--n-cpu <并行核数>]
