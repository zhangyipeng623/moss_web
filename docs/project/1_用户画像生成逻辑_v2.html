MOSS 用户画像生成

技术逻辑与学术参考  |  日期：2026-05-17  |  分支：feat/recsys  |  版本：v2 重构版（Rogers 5 级框架 + P84 单阈值 + 双 Prompt 体系 + 三种 profile_mode）

概述

用户画像生成是 MOSS 社交模拟系统的数据基础层。它通过多阶段 LLM 流水线从原始社交数据中提取结构化用户画像， 为下游的 ABM 参数反推和 Agent 模拟运行提供关键输入。画像生成的质量、一致性和规模直接影响整个系统的模拟保真度。

v2 重构版核心升级：Rogers 5 级创新扩散框架（P84 单阈值切分）、双 Prompt 体系（FIXED_USER_INFO_TEMPLATE + SIMPLE_USER_TEMPLATE）、三种 profile_mode（default / custom / simple）、L1-L3 预设行为库降低 LLM 调用成本。

核心文件：analysis/user_portrait_generator.py（约 1022 行），入口：analysis/run_analysis.py portrait

1. 五阶段 LLM 画像生成流水线

1.1 流水线总览

UserPortraitGenerator.run_pipeline() 编排以下 5 个阶段，每阶段独立重试（通过 _retry_stage，最多 3 次）：

A. 证据抽取 → B. 稳定画像 → C. 行为画像 → D. Agent 画像 → E. 模拟初始状态

阶段 A — 并行分块证据抽取（generate_evidence_pack）：

  • 将用户帖子按时间/影响力排序后分块（每块最多 20 条，最多 6 块）
  • 并行调用 LLM 对每块进行主题信号、价值立场、表达风格、行为模式、人口统计提取
  • 输出 ChunkObservation 列表（topic_candidates, value_signals, style_observations, behavior_signals, demographic_hints）
  • 合并各块观察结果到 EvidencePack，包含去重后的 topic_candidates（最多 12 个）、style_examples（最多 10 个）、behavior_signals（最多 12 个）、demographic_hints（最多 8 个）、value_signals（最多 10 个），计算 coverage_score

阶段 B — 稳定画像生成（generate_stable_profile）：

  • 基于 EvidencePack 生成 StableProfile
  • 包含：language（语言偏好）、long_term_interests（长期兴趣，最多 8 个）、content_topics（内容话题，最多 10 个）、expression_style（ExpressionStyle：tone / formality / verbosity / argument_style）、value_anchors（ValueAnchor：topic + stance + confidence，最多 8 个）、social_role（SocialRole）、demographics（Demographics：age_range / gender / job / education / income）、profile_summary、uncertainties

阶段 C — 行为画像生成（generate_behavior_profile）：

  • 基于 EvidencePack + StableProfile 生成 BehaviorProfile
  • 包含：activity_pattern（ActivityPattern：top_active_hours / recent_activity_level / posting_frequency_level）、action_preferences（ActionPreferences：post / comment / like / repost / quote 五项概率分布）、interaction_preferences（3 个布尔标志）、content_preferences、trigger_rules（TriggerRule：condition + likely_actions + confidence，最多 8 个）

阶段 D — 单主人格 Agent 画像压缩（generate_agent_profile）：

  • 基于 EvidencePack + StableProfile + BehaviorProfile 生成 AgentProfile
  • 核心摘要字段：identity_summary, interest_summary, value_summary, style_summary, behavior_summary, interaction_summary
  • 规则字段：speaking_rules（表达规则，最多 8 条）、action_rules（行动规则，最多 8 条）、avoidance_rules（回避规则，最多 8 条）
  • 附加字段：initial_focus_topics（最多 6 个）、current_goal_hint

阶段 E — 模拟初始状态（generate_simulation_init）：

  • 基于 StableProfile + BehaviorProfile + AgentProfile + 全局事件生成 SimulationInit
  • 包含：mood（情绪）、emotion_reason（情绪原因）、intensity（强度 0-1）、current_goal（当前目标）、focus_topics（关注话题）、stance_summary（立场摘要）、attention_target（注意力目标）
适用范围：完整的 5 阶段 LLM 流水线仅用于 L4-L5 种子用户（约占前 16%）。L1-L3 大众用户通过 preset 配置 + SIMPLE_USER_TEMPLATE 直接使用，不经过此流水线，大幅降低 LLM 调用成本。

1.2 LLM 调用架构

使用 LangChain ChatOpenAI 调用 LLM，通过 _build_llm_callable 包装为统一签名：

async def llm_callable(system_prompt: str, user_prompt: str) -> dict[str, Any]

输入使用 SystemMessage + HumanMessage 格式，返回结果通过 json_repair 库解析为 dict 后再经 Pydantic 模型校验。各阶段均有独立的 Pydantic 输出模型，确保结构化输出质量。

顶层输出模型为 SimulationUserProfile（Pydantic BaseModel），包含上述所有子结构，以及扁平化的模板字段（identity_summary, interest_summary 等）、stats、evidence_meta 和 generation_meta，最终序列化为 JSON 文件。

2. 数据预处理与证据选取

2.1 数据输入

画像生成从 Excel/CSV 数据目录读取，主要数据源：

文件必需列额外列
user.xlsx/csv 用户名, 昵称, 简介, 性别, 地域, 关注, 粉丝, 收藏, 创建时间戳 源用户名, 用户地址, 头像链接
post.xlsx/csv 用户名, 发文内容, 发布时间, 发布时间戳, 发文类型 点赞数, 评论数, 转发数, 帖子ID/推文ID

数据加载函数 _load_tabular_rows 支持 .xlsx（openpyxl）和 .csv 两种格式，自动检测文件类型。

2.2 统计画像计算（UserStats）

在调用 LLM 之前，generator.analyze_stats(source) 计算约 25 个统计指标：

  • 基础统计：post_count, fans_count, follow_count, collect_count, register_date
  • 内容分析：original_ratio, comment_ratio, forward_ratio, quote_ratio, avg_post_length, hashtag/mention/url_post_count
  • 互动统计：avg_like_count, avg_comment_count, avg_share_count, avg_engagement
  • 活跃度：active_day_count, recent_7d/30d_post_count, active_hour_statistic（按小时的发帖分布）, top_active_hours
  • 影响力：post_influence（单帖影响力）, account_influence（核心分级指标，综合粉丝数对数 + 帖子影响力 + 近期活跃度）

2.3 证据帖子选取策略

从全部帖子中筛选高质量证据帖用于 LLM 推理，分层选取：

  • 高影响力帖子（最多 30 条）：综合 like/comment/share 加权 + 时间衰减排序
  • 原始帖子优先：优先选取原创内容（发文类型为"原创"），其次为转发/引用
  • 时间覆盖：尽量覆盖用户活跃时间段内的不同时期
  • 选取后按时间排序分块，每块不超过 20 条，最多 6 块（即最多 120 条证据帖）

3. 影响力分级体系（Rogers 5 级 + P84 单阈值）

3.1 Rogers 创新扩散 5 级框架

v2 重构版采用 Rogers 创新扩散理论（Diffusion of Innovations）的 5 级分类，替代原有的 P60/P90 双阈值三分法：

Tier标签英文Rogers 理论占比分类方式TIER_WEIGHT
5InnovatorsInnovators~2.5%自动：account_influence > P842.0
4Early AdoptersEarly Adopters~13.5%自动：account_influence ≤ P84（批量）/ 单用户默认1.5
3Early MajorityEarly Majority~34%手动：CSV 中设 tier=31.0
2Late MajorityLate Majority~34%手动：CSV 中设 tier=20.7
1LaggardsLaggards~16%手动：CSV 中设 tier=10.4

标签映射函数（analysis/run_analysis.py:_tier_label）：

def _tier_label(tier: int) -> str: labels = { 1: "Laggards", 2: "Late Majority", 3: "Early Majority", 4: "Early Adopters", 5: "Innovators", } return labels.get(tier, f"Lv{tier}")

3.2 P84 单阈值切分机制

v2 重构版将原来的 P60/P90 双阈值改为 P84 单阈值（对应 Rogers 理论中 Innovators + Early Adopters 合计约 16%）：

  • 批量模式：预计算全部用户的 account_influence（无需 LLM），按值排序，取 P84 百分位作为阈值
  • 高于 P84 → tier=5（Innovators），低于或等于 P84 → tier=4（Early Adopters）
  • 单用户模式：无参考群体，默认 tier=4（Early Adopters）
  • Tier 3/2/1（Early Majority / Late Majority / Laggards）不在自动分类中产生，仅通过 agents.csv 的 AgentConfig.tier 字段手动指定
设计理由：LLM 画像生成成本高昂，仅对前 16% 高价值种子用户执行完整 5 阶段流水线。剩余 84% 大众用户通过 SIMPLE_USER_TEMPLATE + TIER_BEHAVIOR 预设行为库低成本生成，实现"精准画像 + 规模化"的平衡。

3.3 account_influence 计算公式

_compute_user_influence 综合三个维度：

account_influence = log(1 + fans_count) * w_fans + mean(post_influence) * w_post + recent_activity_score * w_activity

其中 post_influence 综合单帖的 like/comment/share 加权，recent_activity_score 考量近 30 天发帖频率。三个权重通过标准化后加权求和。

4. 双 Prompt 体系与三种 Profile Mode

4.1 三种 profile_mode

定义在 core/experiment_config.py 的 AgentConfig 中，由 core/agent_profile_resolver.py 解析：

Modeuser_info 来源模板适用场景
"default" 结构化 JSON 画像（内联 dict / JSON 字符串 / profile_path 文件）— 必需 FIXED_USER_INFO_TEMPLATE（9 字段内置模板） L4-L5 种子用户（经完整 LLM 流水线生成画像）
"custom" 结构化 JSON 画像（可选） 用户提供的 user_info_template 或 user_info_template_path — 必需 需要自定义 persona 格式的实验场景
"simple" 自动构建为 {"bio": agent.bio, "tier": agent.tier or 3} SIMPLE_USER_TEMPLATE（内置简化模板） L1-L3 大众用户（无需 LLM 画像，仅需 bio + tier）

解析逻辑位于 core/agent_profile_resolver.py：_resolve_user_info 根据 mode 决定返回什么字段；_resolve_user_info_template 决定使用哪个模板字符串。simple 和 default 模式均返回 None（使用内置模板），只有 custom 模式需要用户提供模板。

4.2 FIXED_USER_INFO_TEMPLATE（9 字段，用于 default 模式）

定义在 moss_agent_client/agent.py，包含 9 个结构化字段：

## 用户身份 {identity_summary} ## 兴趣领域 {interest_summary} ## 价值立场 {value_summary} ## 表达风格 {style_summary} ## 行为模式 {behavior_summary} ## 互动特征 {interaction_summary} ## 表达规则 {speaking_rules_text} ## 行动规则 {action_rules_text} ## 回避规则 {avoidance_rules_text}

这些字段由 UserPortraitGenerator.build_template_fields() 从画像 JSON 中提取。如果任何字段缺失，MossAgent._build_static_context() 会抛出 ValueError。

4.3 SIMPLE_USER_TEMPLATE（用于 simple 模式）

定义在 moss_agent_client/agent.py，仅使用姓名、Bio 和行为期望三个字段：

## 用户身份 姓名：{name} ## 个人简介 {bio} ## 行为期望 {behavior_expectation}

其中 behavior_expectation 来自 TIER_BEHAVIOR[tier] 查找。整个模板仅约 3 个替换字段，远少于 FIXED_USER_INFO_TEMPLATE 的 9 字段，适合大规模 L1-L3 用户。

5. L1-L3 预设行为库

5.1 TIER_BEHAVIOR 定义

定义在 moss_agent_client/agent.py，为每个 Rogers 层级预设中文行为描述：

Tier行为描述
5 (Innovators)重度活跃用户和创新者，热衷于尝试新话题和引领讨论，是社区的意见领袖。喜欢发表深度内容、频繁互动、主动探索新领域。
4 (Early Adopters)较活跃用户，愿意接受新信息并参与讨论，有一定的社交影响力。会选择性参与感兴趣的话题，偶尔发表有见地的内容。
3 (Early Majority)适度活跃用户，在话题热度上升后参与，倾向于跟随主流意见。发帖和互动频率中等，内容以评论和转发为主。
2 (Late Majority)较低活跃度用户，在大众普遍接受后才加入讨论，持观望态度。主要通过浏览和偶尔点赞参与，鲜少发表原创内容。
1 (Laggards)几乎不发帖，以浏览为主，偶尔点赞。对新话题和讨论持保守态度，极少主动发起互动。

在 simple 模式下，MossAgent._build_static_context() 读取 tier 字段并查找 TIER_BEHAVIOR[tier]，若未找到则回退到 tier=3 的行为描述。

5.2 L1-L3 预设用户配置

预设用户通过 configs/experiments/preset_users_l1_l3.csv 配置：

usernamenamebioprofile_modetier
user_l3_001早期大众用户A对热门话题有兴趣…simple3
user_l3_002早期大众用户B关注科技和社会议题…simple3
user_l2_001晚期大众用户A偶尔看看热搜…simple2
user_l2_002晚期大众用户B更喜欢看而不是说…simple2
user_l1_001滞后者A只看不发…simple1
user_l1_002滞后者B偶尔点赞…simple1

CSV 列定义对应 AgentConfig 字段：username, name, bio, profile_mode, tier。tier 通过 field_validator 校验范围 1-5。

6. 输出结构与下游消费

6.1 SimulationUserProfile 顶层结构

画像 JSON 文件（如 analysis_outputs/portraits/<user_name>.json）包含以下顶级字段：

字段类型来源下游消费方
stable_profileStableProfile阶段 BABM 种群合成（_portrait_to_persona 提取 content_topics, value_anchors）
behavior_profileBehaviorProfile阶段 CABM 行为参数
agent_profileAgentProfile阶段 DAgent 模拟（build_template_fields 提取 9 字段）
simulation_initSimulationInit阶段 EAgent 初始状态设定
statsUserStats预处理影响力分级（account_influence）
influence_tierint批量分级ABM TIER_WEIGHT 加权、Agent tier 行为选择
influence_tier_labelstr批量分级可读标签
identity_summary 等strbuild_template_fieldsAgent FIXED_USER_INFO_TEMPLATE 插值

6.2 下游消费路径

画像 JSON → ABM: _portrait_to_persona → 种群合成 → 推荐参数反推
画像 JSON → Agent: build_template_fields → FIXED_USER_INFO_TEMPLATE → LLM 决策

_portrait_to_persona（recommender_parameter_inference.py）从画像中提取：label（来自 value_anchors[0].stance）、user_info（来自 agent_profile.identity_summary，fallback 到 stable_profile.profile_summary）、topic（来自 content_topics）、account_influence、influence_tier。

7. 批量模式 vs 单用户模式

7.1 批量模式（--batch）

命令：uv run python -m analysis.run_analysis portrait --data-path <目录> --batch

三阶段流程：

  1. 阶段 1 — 预计算影响力：遍历全部用户，调用 generator.analyze_stats() 计算 account_influence，无需 LLM
  2. 阶段 2 — P84 层级分配：按 account_influence 排序，P84 以上 → tier=5 (Innovators)，其余 → tier=4 (Early Adopters)
  3. 阶段 3 — 并行 LLM 画像生成：对全部用户并行执行 5 阶段流水线，跳过已存在的画像文件（但会原地更新其 tier 字段），每个用户最多重试 3 次，失败条目写入 failed_users.json

7.2 单用户模式（--user-name）

命令：uv run python -m analysis.run_analysis portrait --data-path <目录> --user-name <用户名>

  • 读取 user.xlsx 中该用户的数据和 post.xlsx 中其帖子数据
  • 执行完整 5 阶段流水线
  • influence_tier 硬编码为 4（Early Adopters），无参考群体可比
  • 输出到 analysis_outputs/portraits/<user_name>.json

7.3 retier 命令

命令：uv run python -m analysis.run_analysis retier --portraits-dir <画像目录>

对已生成的画像 JSON 文件重新执行 P84 层级分配（不重新调用 LLM），适用于新增用户后需要重新校准层级分布的场景。
