# 在线社交模拟

> 毕业设计项目：MOSS Web 社交媒体舆情模拟推演平台
> 完成人：张艺鹏（个人完成）
> 文档范围：在线平台的进程模型、Backend 服务、推荐打分、Agent 决策与记忆、大小模型分层与运行归档。

## 1. 功能目标

在线平台承载“校准参数注入 + 多 Agent 社交仿真 + 浏览器观察”的运行闭环：加载 `calibration_profile.yaml`，启动 Backend 与 Agent 两个进程，让画像驱动的 LLM Agent 在一个带推荐流、模拟时间和互动计数的虚拟社交网络中持续行动（感知—决策—动作—记忆更新），并把全过程归档到 `runs/<run_id>/`。

## 2. 进程模型

`main.py` 通过 `multiprocessing`（spawn 模式）启动两个独立进程：

- **Backend 进程**（`start_backend`）：FastAPI 服务（端口 8000），托管 REST API 与前端静态资源。因 spawn 会重新 import 模块、主进程的类属性不会跨进程传递，校准参数在子进程内、`create_app()` 之前再次通过 `SocialRecSys.configure()` 注入。
- **Agent 进程**（`start_agent`）：运行 `AgentGraph` 循环，遍历 CSV/画像配置的 Agent，经 `ChatOpenAI` 决策后调用 Backend API 执行动作。

主进程先启动 Backend 并在 30 秒内做健康检查，就绪后再启动 Agent。

## 3. Backend 服务

| 组件 | 职责 | 关键位置 |
|---|---|---|
| 路由 | 登录、信息流、帖子、评论、点赞/转发/引用、轨迹、时间 | `backend/routers/api.py` |
| DAO | 用户与帖子的 SQLite 读写、互动计数、轨迹查询 | `backend/dao/` |
| 向量存储 | `sqlite-vec` 扩展，帖子内容嵌入存于 `posts_vec` | `backend/dao/database.py` |
| 推荐服务 | `SocialRecSys`，向量候选 + 四维打分排序 | `backend/services/social_recsys.py` |
| 时间服务 | 步进模式（step）或真实时间，模拟时钟 | `backend/services/time_service.py` |

### API 概览

- `POST /api/v1/login` — 注册/登录 Agent；已存在用户刷新 `tier`/`belief_text`
- `GET /api/v1/feed?user_id=&limit=` — 个性化信息流
- `GET /api/v1/posts?limit=&offset=` — 全量帖子列表
- `GET /api/v1/posts/{post_id}` — 帖子详情（不存在返回 404）
- `POST /api/v1/posts` / `POST /api/v1/comments` — 发帖/评论
- `POST /api/v1/posts/like|repost|quote` / `POST /api/v1/comments/like` — 互动
- `GET /api/v1/traces` — 近期行为轨迹
- `GET/POST /api/v1/time` — 模拟时间查询与步进
- `GET /api/v1/health` — 健康检查（绕过 SPA 挂载）

发帖与引用在创建后同步生成内容向量写入 `posts_vec`。

## 4. 推荐打分

`SocialRecSys` 综合四个加权分数（公式与离线 ABM 共用 `core/scoring.py`）：

| 维度 | 公式 | 权重来源 |
|---|---|---|
| 兴趣 `W_BELIEF` | 用户立场文本与帖子内容的余弦相似度 | YAML `recommender.weights.w_interest` |
| 热度 `W_POP` | `log1p(加权互动)/log1p(N)` × `TIER_WEIGHT[作者tier]` | YAML `w_popularity` |
| 时效 `W_CHRONO` | `exp(-decay_lambda × dt_hours)` | YAML `w_time` |
| 探索 `W_RAND` | 均匀随机 | YAML `w_random` |

权重由 `SocialRecSys.configure()` 从 YAML 自动注入，不再硬编码。嵌入模型名由 YAML `embedding.model_name` 配置（默认 `BAAI/bge-m3`），编码时按 `normalize_embeddings` 控制归一化。候选生成优先走 `sqlite-vec` 相似度检索（取 top 100）；无立场文本、无向量或检索异常时回退到按时间倒序。

## 5. Agent 决策循环

`AgentGraph` 负责多 Agent 的调度（[agent_graph.py](/Users/zhangyipeng/Documents/moss_web/moss_agent_client/agent_graph.py)）：

- `load_from_config` 批量创建 Agent；`start_all` 并发注册/登录；`step_all` 并发执行每轮决策；
- 任一 Agent 在本轮执行失败会中止整轮（`step_all` 抛错），避免重复副作用动作污染实验数据；
- 每轮结束后按 `system_time` 步进模拟时钟。

`MossAgent` 是单个 Agent 的执行体（[agent.py](/Users/zhangyipeng/Documents/moss_web/moss_agent_client/agent.py)）：用 LangChain `create_agent` 把 `ChatOpenAI` 与动作工具绑定，`temperature=0` 固定采样以保证可复现。

## 6. 画像注入

Agent 通过 `profile_mode` 选择画像模板：

- `default`：注入 5 阶段生成的完整结构化画像（`FIXED_USER_INFO_TEMPLATE`，九项固定字段）；
- `custom`：注入自定义模板；
- `simple`：注入 `SIMPLE_USER_TEMPLATE`（bio + 按 tier 的行为预期），供低层级预设用户低成本驱动。

`belief_text`（default/custom 用 `identity_summary + interest_summary`，simple 用 bio）随注册写入数据库，供在线推荐做语义匹配。

## 7. 动作工具

动作规格集中在 `moss_agent_client/actions.py`，通过 `StructuredTool` 暴露给 LLM：发帖、评论、点赞帖子、转发、引用、点赞评论、不动作（do_nothing）。每个动作经 `RemotePlatform` 调 Backend API，结果回写 `ActionTrace` 留痕。

## 8. 记忆系统

记忆模型定义在 `memory.py`，管理逻辑在 `memory_manager.py`：

| 记忆 | 结构 | 说明 |
|---|---|---|
| 静态上下文 | `StaticContext` | 画像文本 + 全局事件，全程不变 |
| 短期记忆 | `ShortTermMemory` | 最近 N 轮（默认 3）的环境快照 + 动作 + 输出 |
| 事件记忆 | `EventMemory` | 最多 50 条，按 `importance` 降序，去重合并 |
| 动态状态 | `AgentState` | mood/emotion/intensity/current_goal/focus_topics/stance/attention_target |

每轮决策后，LLM 输出结构化 `DecisionResultPayload`（状态更新 + 事件记忆写入），`MemoryManager.update_after_step` 据此更新状态与事件记忆；结构化解析失败时保留上一轮状态，不污染记忆。

## 9. 事件记忆检索

`select_relevant_events` 用乘法评分 + 时间衰减从事件记忆取相关记录：

```
score = importance × exp(-λ × rounds_ago) × (1 + min(context_boost, cap))
```

- `importance`：Agent 当初自评的重要度（乘法保证低重要性事件无法反超高重要性事件）；
- 时间衰减：Ebbinghaus 遗忘曲线，`λ` 可配置（默认 0.07，半衰期约 10 轮）；
- 上下文联想：引用提醒、相关人物出现、话题命中当前关注等，加成上限 0.3，锦上添花不喧宾夺主。

记忆参数（窗口/容量/衰减/加成）由 `calibration_profile.yaml` 的 `simulation.memory` 段注入。

## 10. 大小模型分层

在“画像成本分层”（default 走 5 阶段画像、simple 走 bio+预设）之上，进一步把 **LLM 层**也分层：

- **core（核心用户，default，L4/L5）**：大模型（DeepSeek）；
- **mass（普通用户，simple，L1–L3）**：小模型（Qwen 自部署，或兼容端点）。

实现方式（已落地）：`ExperimentConfig`/`ExperimentYamlConfig` 增加可选 `llm_small` 段（缺省 None 表示未启用，退化为全员大模型）；`AgentGraph.add_agent` 按 `profile_mode` 分流选 llm；`main.py` 抽出 `_build_llm()` 复用并构建小模型；`.env` 增加小模型 `BASE_URL_SMALL`/`API_KEY_SMALL`。对照实验为“全员大模型” vs “core 大模型 + mass 小模型”，比传播量分布（KS）、内容排序（Spearman）与 token 成本。

## 11. 运行归档

每次运行在 `runs/<运行ID>/` 下生成独立归档：`moss.db`、`backend.log`、`agent.log`、`experiment.snapshot.json`（配置快照）。数据库路径由 `MOSS_DB_PATH` 指向当次运行目录，避免跨运行污染。
