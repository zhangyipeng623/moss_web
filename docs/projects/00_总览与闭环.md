# MOSS Web：总览与三者闭环

> 毕业设计项目：MOSS Web 社交媒体舆情模拟推演平台
> 完成人：张艺鹏（个人完成）

## 1. 项目定位

MOSS Web 是本人独立完成的毕业设计实验平台，用于把社交媒体用户画像、推荐参数校准与多智能体社交仿真组织为可观察、可归档的研究流程。系统由离线分析链路和在线仿真链路组成：离线生成用户画像并反推推荐参数，在线用 LLM Agent 在虚拟社交网络中执行发帖、评论、点赞、转发和引用等行为。

当前总入口为 `main.py`：它加载校准 YAML，创建单次运行目录，并分别启动 Backend 与 Agent 进程（[main.py](/Users/zhangyipeng/Documents/moss_web/main.py)）。离线统一入口是 `analysis.run_analysis`，提供 `portrait`、`recommender`、`retier` 三个子命令（[analysis/run_analysis.py](/Users/zhangyipeng/Documents/moss_web/analysis/run_analysis.py)）。

## 2. 系统边界与架构

```text
用户/帖子表格 ──> 画像生成 ──> 画像 JSON ─┐
                                           ├─> 校准 YAML ──> 在线推演
传播观测表 ──> ABM + EM 校准 ──> 权重/概率 ─┘                  │
                                                              ├─> FastAPI + SQLite/vec
浏览器观察面板 <───────────────────────────────────────────────┤
                                                              └─> LLM 多 Agent
```

主要模块如下：

| 领域 | 模块 | 职责 |
|---|---|---|
| 运行编排 | `main.py`、`core/` | 配置、进程、运行归档、日志 |
| 平台服务 | `backend/` | API、DAO、SQLite/sqlite-vec、推荐与模拟时间 |
| Agent | `moss_agent_client/` | 画像注入、决策循环、工具调用、记忆 |
| 离线分析 | `analysis/` | 用户画像、分层、ABM/EM 推荐校准 |
| 观察前端 | `frontend/` | 帖子流、轨迹、时间与帖子详情 |

单次实验的运行状态保存在 `runs/<run_id>/`：数据库、后端日志、Agent 日志和配置快照由 `RunContext` 定义（[core/runtime.py](/Users/zhangyipeng/Documents/moss_web/core/runtime.py)）。

## 3. 三者闭环（单一配置源）

系统的核心是「用户画像 → 参数校准 → 社交模拟」的端到端闭环，由**单一配置源 `calibration_profile.yaml`** 驱动：

```
user/post.xlsx → portrait 画像生成 → portraits/*.json
portraits/*.json + 内容观测.xlsx → recommender ABM/EM 校准 → calibration_profile.yaml
calibration_profile.yaml → main.py → 注入 → 在线社交仿真 → runs/<ID>/
```

### 统一校准 YAML

`CalibrationProfile` 以 Pydantic 表达五段（[calibration_profile.py](/Users/zhangyipeng/Documents/moss_web/core/calibration_profile.py)）：

| 段 | 内容 |
|---|---|
| `meta` | 生成时间、画像目录、种子数、ABM 规模、输入数据文件 |
| `experiment` | 名称、描述、`global_event`、`llm`、`llm_small`、`agents_csv`、`portrait`、`system_time`、`runtime` |
| `recommender` | `weights`（w_interest/w_popularity/w_time/w_random）、`decay_lambda`、`tier_weight`、`calibrated_p_base`、`fit_diagnostics` |
| `embedding` | `model_name`（默认 `BAAI/bge-m3`）、`normalize_embeddings` |
| `simulation` | `p_online`、`belief_update`、`content_filter`、`feed`、`memory` |

`main.py --config <calibration_profile.yaml>` 是唯一在线入口，不直接加载旧 `experiment.json`。

### 配置注入

`main.py` 加载 YAML 后，`to_experiment_config()` 把 `experiment` 段转为 `ExperimentConfig`，并在主进程与 Backend 子进程内分别调用 `SocialRecSys.configure(recommender, embedding)` 注入推荐权重与嵌入模型（[main.py](/Users/zhangyipeng/Documents/moss_web/main.py)）。Agent 进程消费 `experiment` 段构造 LLM（含小模型）与记忆参数。配置快照写入 `runs/<id>/experiment.snapshot.json`，故 API key 只留在 `.env`、不进 YAML。

主线能力已闭环并通过 `test.py` 49 项验证脚本覆盖：
