# 在线社交仿真平台

> 毕业设计项目：MOSS Web 社交媒体舆情模拟推演平台
> 完成人：张艺鹏（个人完成）
> 文档范围：在线平台的进程模型、Backend 服务、推荐打分与运行归档。

## 1. 功能目标

在线平台承载“校准参数注入 + 多 Agent 社交仿真 + 浏览器观察”的运行闭环：加载 `calibration_profile.yaml`，启动 Backend 与 Agent 两个进程，让画像驱动的 LLM Agent 在一个带推荐流、模拟时间和互动计数的虚拟社交网络中行动，并把全过程归档到 `runs/<run_id>/`。

## 2. 进程模型

`main.py` 通过 `multiprocessing`（spawn 模式）启动两个独立进程：

- **Backend 进程**（`start_backend`，[main.py](/Users/zhangyipeng/Documents/moss_web/main.py:88)）：FastAPI 服务（端口 8000），托管 REST API 与前端静态资源。因 spawn 会重新 import 模块、主进程的类属性不会跨进程传递，校准参数在子进程内、`create_app()` 之前再次通过 `SocialRecSys.configure()` 注入（[main.py](/Users/zhangyipeng/Documents/moss_web/main.py:109)）。
- **Agent 进程**（`start_agent`，[main.py](/Users/zhangyipeng/Documents/moss_web/main.py:127)）：运行 `AgentGraph` 循环，遍历 CSV/画像配置的 Agent，经 `ChatOpenAI` 决策后调用 Backend API 执行动作。

主进程先启动 Backend 并在 30 秒内做健康检查，就绪后再启动 Agent（[main.py](/Users/zhangyipeng/Documents/moss_web/main.py:242)）。

## 3. Backend 服务

| 组件 | 职责 | 关键位置 |
|---|---|---|
| 路由 | 登录、信息流、帖子、评论、点赞/转发/引用、轨迹、时间 | `backend/routers/api.py` |
| DAO | 用户与帖子的 SQLite 读写、互动计数、轨迹查询 | `backend/dao/` |
| 向量存储 | `sqlite-vec` 扩展，帖子内容嵌入存于 `posts_vec` | `backend/dao/database.py` |
| 推荐服务 | `SocialRecSys`，向量候选 + 四维打分排序 | `backend/services/social_recsys.py` |
| 时间服务 | 步进模式（step）或真实时间，模拟时钟 | `backend/services/time_service.py` |

### API 概览

- `POST /api/v1/login` — 注册/登录 Agent；已存在用户刷新 `tier`/`belief_text`（[api.py](/Users/zhangyipeng/Documents/moss_web/backend/routers/api.py:57)）
- `GET /api/v1/feed?user_id=&limit=` — 个性化信息流
- `GET /api/v1/posts?limit=&offset=` — 全量帖子列表
- `GET /api/v1/posts/{post_id}` — 帖子详情（不存在返回 404）
- `POST /api/v1/posts` / `POST /api/v1/comments` — 发帖/评论
- `POST /api/v1/posts/like|repost|quote` / `POST /api/v1/comments/like` — 互动
- `GET /api/v1/traces` — 近期行为轨迹
- `GET/POST /api/v1/time` — 模拟时间查询与步进
- `GET /api/v1/health` — 健康检查（绕过 SPA 挂载）

发帖与引用在创建后同步生成内容向量写入 `posts_vec`（[api.py](/Users/zhangyipeng/Documents/moss_web/backend/routers/api.py:105)）。

## 4. 推荐打分

`SocialRecSys` 综合四个加权分数（公式与离线 ABM 共用 `core/scoring.py`）：

| 维度 | 公式 | 权重来源 |
|---|---|---|
| 兴趣 `W_BELIEF` | 用户立场文本与帖子内容的余弦相似度 | YAML `recommender.weights.w_interest` |
| 热度 `W_POP` | `log1p(加权互动)/log1p(N)` × `TIER_WEIGHT[作者tier]` | YAML `w_popularity` |
| 时效 `W_CHRONO` | `exp(-decay_lambda × dt_hours)` | YAML `w_time` |
| 探索 `W_RAND` | 均匀随机 | YAML `w_random` |

权重由 `SocialRecSys.configure()` 从 YAML 自动注入（[social_recsys.py](/Users/zhangyipeng/Documents/moss_web/backend/services/social_recsys.py:34)），不再硬编码。嵌入模型名由 YAML `embedding.model_name` 配置（默认 `BAAI/bge-m3`），编码时按 `normalize_embeddings` 控制归一化（[social_recsys.py](/Users/zhangyipeng/Documents/moss_web/backend/services/social_recsys.py:59)）。

候选生成优先走 `sqlite-vec` 相似度检索（取 top 100）；无立场文本、无向量或检索异常时回退到按时间倒序（[social_recsys.py](/Users/zhangyipeng/Documents/moss_web/backend/services/social_recsys.py:167)）。

## 5. 运行归档

每次运行在 `runs/<运行ID>/` 下生成独立归档：`moss.db`、`backend.log`、`agent.log`、`experiment.snapshot.json`（配置快照）。数据库路径由 `MOSS_DB_PATH` 指向当次运行目录，避免跨运行污染。
