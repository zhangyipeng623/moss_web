# 分层用户与闭环配置

> 毕业设计项目：MOSS Web 社交媒体舆情模拟推演平台
> 完成人：张艺鹏（个人完成）
> 文档范围：Rogers 用户分层、画像模式接入、`calibration_profile.yaml` 统一配置与大小模型分层方案。

## 1. 功能目标

在线推演同时需要两类用户：由历史数据生成完整结构化画像的核心用户，与补足总体分布的低活跃预设用户。同时，离线校准产出的权重、衰减系数与嵌入模型配置需进入在线实验，使“画像生成 → 参数反推 → 模拟运行”闭环为单一配置源驱动的流程。

## 2. 用户分层

分层由两个正交维度组成：

- **画像模式 `profile_mode`**（决定“用什么画像驱动”）：
  - `default`：5 阶段生成的完整结构化画像；
  - `custom`：自定义模板 + 内联/文件画像；
  - `simple`：仅 bio + 按 tier 的行为预设（`SIMPLE_USER_TEMPLATE`），供低层级预设用户低成本驱动。
- **层级 `tier`（1–5，Rogers 创新扩散）**（决定“传多远 / 多活跃”）：
  - 作为行为与影响力参数贯穿全链路：`TIER_WEIGHT`（热度打分作者加权）、`simulation.p_online`（ABM 在线概率）、`TIER_BEHAVIOR`（simple 用户活跃度描述）。

`AgentConfig` 校验 `profile_mode` 取值与 `tier` 范围（[experiment_config.py](/Users/zhangyipeng/Documents/moss_web/core/experiment_config.py:15)），`resolve_agent_payloads` 按模式解析画像并透传 `profile_mode`（[agent_profile_resolver.py](/Users/zhangyipeng/Documents/moss_web/core/agent_profile_resolver.py:13)）。

批量画像按 **P84 单阈值**把真实用户切成 L4/L5（核心用户），L1–L3 由 `agents.csv` 里的 simple 预设行补充。

## 3. 统一校准 YAML

`CalibrationProfile` 以 Pydantic 表达五段（[calibration_profile.py](/Users/zhangyipeng/Documents/moss_web/core/calibration_profile.py:106)）：

| 段 | 内容 |
|---|---|
| `meta` | 生成时间、画像目录、种子数、ABM 规模、输入数据文件 |
| `experiment` | 名称、描述、`global_event`、`llm`、`agents_csv`、`portrait`、`system_time`、`runtime` |
| `recommender` | `weights`（w_interest/w_popularity/w_time/w_random）、`decay_lambda`、`tier_weight`、`calibrated_p_base`、`fit_diagnostics` |
| `embedding` | `model_name`（默认 `BAAI/bge-m3`）、`normalize_embeddings` |
| `simulation` | `p_online`、`belief_update`、`content_filter`、`feed`、`memory` |

`main.py --config <calibration_profile.yaml>` 是唯一在线入口，不直接加载旧 `experiment.json`。

## 4. 配置注入

`main.py` 加载 YAML 后，`to_experiment_config()` 把 `experiment` 段转为 `ExperimentConfig`，并在主进程与 Backend 子进程内分别调用 `SocialRecSys.configure(recommender, embedding)` 注入推荐权重与嵌入模型（[main.py](/Users/zhangyipeng/Documents/moss_web/main.py:109)）。Agent 进程消费 `experiment` 段构造 LLM 与记忆参数。配置快照写入 `runs/<id>/experiment.snapshot.json`，故 API key 只留在 `.env`、不进 YAML。

## 5. 大小模型分层方案（待实施）

在现有“画像成本分层”（default 走 5 阶段画像、simple 走 bio+预设）之上，进一步把 **LLM 层**也分层：

- **core（核心用户，default，L4/L5）**：大模型（DeepSeek）；
- **mass（普通用户，simple，L1–L3）**：小模型（Qwen 自部署，或兼容端点）。

实现要点：`ExperimentConfig` 增加可选 `llm_small` 段（缺省 None 表示未启用，退化为全员大模型）；`AgentGraph.add_agent` 按 `profile_mode` 分流选 llm；`.env` 增加小模型 `BASE_URL`/`API_KEY`。对照实验为“全员大模型” vs “core 大模型 + mass 小模型”，比传播量分布（KS）、内容排序（Spearman）与 token 成本。
