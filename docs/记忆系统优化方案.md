# 记忆系统优化方案：检索评分 + 时间衰减

## Context

当前记忆系统设计思路正确——短期记忆（3 轮滑动窗口）模拟浏览片段，EventMemory 存储 Agent 自主选择的重要事件。但 `select_relevant_events` 的检索评分公式存在缺陷：规则加分（+1.0/+0.7/+0.5）可以轻易压倒 Agent 自己的重要性判断。

本次优化不改架构、不上向量检索、不增加耗时。仅修改评分公式和补充时间衰减。

### 2. `moss_agent_client/memory_manager.py` — 重写 select_relevant_events

**核心变更**：检索评分从加法模型改为乘法模型。

```python
def select_relevant_events(
    self,
    snapshot: EnvironmentSnapshot,
    current_round: int,
    top_k: int = 5,
) -> list[EventMemoryRecord]:
    if not self.context.event_memory.records:
        return []

    current_post_ids = {item.post_id for item in snapshot.feed_items}
    current_authors = {
        item.author_name for item in snapshot.feed_items if item.author_name
    }
    current_text = snapshot.combined_text()
    focus_topics = set(self.context.state.focus_topics)

    scored_records = []
    for record in self.context.event_memory.records:
        # 1. 主信号：Agent 当初自己评的重要性
        score = record.importance

        # 2. 时间衰减：Ebbinghaus 遗忘曲线，半衰期 ~10 轮
        rounds_ago = max(0, current_round - record.round_id)
        recency = math.exp(-DECAY_LAMBDA * rounds_ago)
        score *= recency

        # 3. 上下文联想加成（上限 0.3，锦上添花不喧宾夺主）
        context_boost = 0.0
        if record.source_post_id in current_post_ids:
            context_boost += 0.05   # 引用/转发提醒
        if any(user in current_authors for user in record.related_users):
            context_boost += 0.12   # 看到相关人物
        if record.topic in focus_topics:
            context_boost += 0.10   # 匹配当前关注
        if record.topic and record.topic in current_text:
            context_boost += 0.03   # Feed 文本中出现话题词

        score *= (1.0 + min(context_boost, 0.3))

        scored_records.append((score, record))

    scored_records.sort(key=lambda item: item[0], reverse=True)
    return [record for _, record in scored_records[:top_k]]
```

**当前公式（旧）**：
```
score = importance + 1.0(post_id匹配) + 0.7(作者匹配) + 0.5(话题匹配) + 0.3(关注匹配) + 0.2(注意力匹配)
```

**新公式**：
```
score = importance × exp(-λ × rounds_ago) × (1 + min(context_boost, 0.3))

context_boost = 0.05(帖子ID) + 0.12(作者) + 0.10(关注主题) + 0.03(话题文本)
```

**关键特性**：乘法保证低重要性事件永远不可能反超高重要性事件。

| 场景 | 旧公式 | 新公式 |
|------|--------|--------|
| importance=0.9，无上下文匹配，距今 0 轮 | 0.9 | 0.90 |
| importance=0.3，作者+话题+帖子全匹配，距今 0 轮 | 2.5 ❌ 反超 | 0.39 |
| importance=0.9，全匹配，距今 0 轮 | 3.1 | 1.17 |
| importance=0.9，无匹配，距今 20 轮 | 0.9 | 0.12（自然淡出） |

## 参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `DECAY_LAMBDA` | `0.07` | 时间衰减系数，半衰期 ~10 轮（`ln(2)/0.07 ≈ 9.9`） |
| `CONTEXT_BOOST_CAP` | `0.3` | 上下文加成上限，防止规则匹配主导 |
| `TOP_K` | `5` | 返回的相关事件数（不变） |

`DECAY_LAMBDA` 备选值：
- `0.05` → 半衰期 ~14 轮，适合慢节奏长周期模拟
- `0.10` → 半衰期 ~7 轮，适合快节奏短周期模拟

建议写入 `calibration_profile.yaml` 的 `simulation.memory` 段，可配置。

## 验证方案

1. **单元验证**：构造 3 条 EventMemoryRecord（不同 importance 和 round_id），模拟 Feed 上下文，验证返回排序正确
2. **边界验证**：importance=1.0 + 全匹配 + 最新轮 vs importance=0.1 + 无匹配 + 远古轮，确认前者始终排前
3. **时间衰减验证**：同一条记录，分别在 rounds_ago=0/7/14/21 时检索，确认分数按指数下降
4. **集成验证**：跑一轮完整模拟，观察 Agent 日志中 `select_relevant_events` 返回的事件是否合理
