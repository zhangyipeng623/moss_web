# MOSS Web

MOSS Web 是一个面向舆情模拟推演的实验项目。系统通过 FastAPI 提供本地实验平台，通过多智能体在虚拟社交环境中的发帖、评论、点赞和转发行为，观察事件传播与干预效果。

## 项目目标

- 将推演逻辑与具体实验场景分离，支持复用实验框架。
- 每次运行自动生成独立归档，便于复现实验与对比结果。
- 使用前端页面观察帖子流、系统时间和行为轨迹。

## 目录说明

- `main.py`：实验启动入口，负责创建本次运行目录、启动后端与 Agent 进程。
- `core/`：运行时归档、日志配置和实验配置加载等基础模块。
- `backend/`：本地实验平台，提供帖子、评论、时间推进、轨迹查询等接口。
- `backend/static/`：前端构建后的静态资源目录，由后端直接提供访问。
- `moss_agent_client/`：Agent 执行逻辑、平台访问封装与多智能体调度。
- `frontend/`：前端源码目录，开发态通过 Vite 运行，生产态构建到 `backend/static/`。
- `configs/experiments/`：实验配置文件目录。
- `runs/`：每次实验的归档目录，默认不纳入版本控制。

## 环境要求

- Python 3.12 及以上
- Node.js 与 npm，用于前端开发和构建
- 已安装项目依赖
- 可访问的模型服务

## 运行流程

### 首次准备

1. 安装 Python 依赖。
2. 安装前端依赖。
3. 配置环境变量。
4. 构建前端静态资源，确保 `backend/static/` 是最新产物。

### 日常运行

1. 确认实验配置文件。
2. 启动 `main.py`。
3. 程序会先创建本次实验的运行目录。
4. 后端启动并初始化本次实验数据库。
5. Agent 进程启动并按实验配置执行推演。
6. 前端页面由后端直接提供，用于观察帖子流和 Trace。

## 前端开发与构建

前端有两种工作方式：

- 开发态：在 `frontend/` 目录中运行开发服务器，用于快速调样式和交互。
- 实验运行态：前端必须先构建，构建产物直接输出到 `backend/static/`，后端运行时加载这一份静态资源。

当前构建链路已经统一为：

- 前端源码位于 `frontend/src/`
- 前端构建输出位于 `backend/static/`
- 后端始终从 `backend/static/` 提供页面访问

这样做的目的是避免以前那种“`frontend/dist` 和 `backend/static` 两份产物并存”的分叉问题。

## 运行归档

每次运行都会在 `runs/时间戳/` 下生成独立归档，默认包含：

- `backend.log`：后端服务日志
- `agent.log`：Agent 运行日志
- `moss.db`：本次实验数据库
- `experiment.snapshot.json`：本次实验实际使用的配置快照

这意味着一次实验的输入、过程和数据会落在同一个目录中，便于：

- 回看单次实验过程
- 对比多次实验结果
- 保留实验输入与输出的对应关系

## 数据说明

- 数据库会按单次实验创建，不再依赖当前工作目录决定落盘位置。
- 每次新运行都会生成新的数据库文件，避免不同实验之间互相污染。
- 轨迹数据会写入数据库中的 `trace` 表。
- 后端日志和 Agent 日志分别写入独立文件。

## 前端页面说明

当前前端主要承担实验观察功能，包括：

- 帖子流展示
- 系统时间展示
- Trace 行为面板
- 详情页查看帖子与评论

它目前更偏“实验观察面板”，不是完整的实验配置工作台。

## 当前约束

- 每次运行默认是一次新的实验，不复用上一次数据库。
- 推演结果仍然会受到模型输出和实验参数的影响。
- 如果修改了前端源码，必须重新构建后端静态资源。
- 目前归档了日志、数据库和配置快照，但还没有自动生成结果摘要。

## 建议的使用方式

- 先固定实验配置，再运行推演。
- 每次实验完成后，直接进入对应的 `runs/` 目录查看日志、数据库和配置快照。
- 如果要做横向比较，建议保留多个运行目录，不要手动覆盖。
